第 08 章 · 面向对象

类与对象： 换一种方式组织代码

前面的章节里，数据和操作是分开的：一堆变量配一堆方法。面向对象把它们捆在一起，让「一个学生」同时拥有姓名、成绩和行为。这不是语法变化，而是思维方式的切换——这一章是整门课的分水岭。

约 80 分钟 9 个知识点 面向对象基石 前置：第 07 章

学完这一章，你应该能够

  • 用「属性 + 行为」描述一个现实事物
  • 写出带参/无参构造器并解释职责
  • 用 this 解决同名与构造器复用
  • 列出成员变量与局部变量的五处差异
  • 用封装保护对象的状态
  • 说清 static 与非 static 的边界
  • 解释 new 一个对象的完整顺序

8.1先想「有哪些事物」，再想「怎么算」

面向对象的第一步不是写类，而是识别对象。

假设要做一个学生成绩管理功能。面向过程的思路是：定义一个数组存成绩、定义几个方法算总分、算平均、排序。数据和方法是分离的，方法多了以后，谁都能改数组，改坏了也查不出来。

面向对象的思路是先问：这里有哪些「事物」？学生、课程、班级。每个事物有自己的属性（姓名、学号、成绩）和行为（选课、计算绩点）。把这些打包成一个类，数据就只能通过它自己提供的方法来访问，边界清晰了。

类与对象

类是模板，描述一类事物共有的属性和行为，写在代码里。对象是按模板创建出来的具体实例，存在于内存中。一个类可以创建无数个对象，每个对象有自己独立的属性值，但共享同一份方法代码。

类与对象java
public class Student {
    String name;          // 属性
    int age;
    double score;

    void introduce() {    // 行为
        System.out.println(name + "，" + age + " 岁");
    }
}

Student s = new Student();   // 创建对象
s.name = "张三";
s.introduce();

对象的内存结构值得想清楚：s 这个引用在栈上，对象实体在堆上，三个属性依次排在实体里。方法不在对象里——方法只有一份，存在方法区，调用时通过隐式的 this 知道操作的是哪个对象。这也解释了两个对象为什么互不影响：它们的属性各自独立。

8.2构造器：对象出生的那一刻

它的唯一职责，是把对象初始化成一个合法状态。

new 的时候会自动调用构造器。构造器名字必须与类名相同、没有返回值类型（连 void 都不能写）。它的意义在于：保证对象一旦被创建出来，就是可用的，而不是一堆默认值。

如果不写任何构造器，编译器会自动补一个公共无参构造器。但只要你手写了任意一个构造器，这个赠送就取消了——这也是为什么很多框架要求实体类必须有显式无参构造器：它们通过反射创建对象，找不到就报错。

构造器重载与复用java
public Student() { }                       // 无参：留给框架

public Student(String name, int age) {
    this.name = name;                      // this 区分成员与参数
    this.age = age;
}

public Student(String name, int age, double score) {
    this(name, age);                       // 复用上面的构造器
    this.score = score;
}

实际项目中常见的写法是「全参构造 + 无参构造」并存：全参方便手写创建，无参供框架反射使用。构造器里还应做基本校验（如年龄不能为负），让非法对象根本创建不出来——这是比 setter 校验更早的一道防线。

8.3this：当前对象的引用

它解决两个问题：变量同名、构造器复用。

this 是一个隐式参数，指向「正在调用这个方法的对象」。当成员变量和参数同名时，不加 this 会优先使用参数（就近原则），加了 this 才明确指成员变量。这是 this 最常见的用途。

第二个用途是 this(...) 调用本类的另一个构造器，用来避免重复的初始化代码。它必须写在构造器第一行，且不能和 super(...) 同时出现——因为两者都要求占据第一行。

第三个用途是返回 this 实现链式调用，很多框架的 Builder 模式和 StringBuffer 的 append 都是这个套路。

static 方法里没有 this

静态方法属于类，调用它的时候可能根本没有对象存在，所以 this 无从指向。在 static 方法里使用 this 会直接编译报错，这也是「静态方法不能访问实例成员」的根本原因。

8.4成员变量与局部变量：两种生命周期

放在哪里，决定了它活多久、谁能看见、有没有默认值。

对比项成员变量局部变量
声明位置类体中、方法外方法体、代码块、参数列表
存储位置堆（属于对象）栈（属于方法调用）
默认值有（0 / 0.0 / false / null）无，必须先赋值
生命周期对象创建到被回收方法进栈到出栈
修饰符可用访问修饰符、static、final只能用 final
内存共享每个对象一份每次调用一份

这六条差异其实可以归结为一句话：成员变量是对象的状态，局部变量是方法的临时工。状态要长期保存、要能被多个方法共享，所以放在堆上随对象走；临时工用完就撤，所以放在栈上，随方法结束而销毁。

理解这一点，就能明白为什么递归时局部变量不会互相干扰（每次调用都有独立的栈帧），也能明白为什么把大数组声明为成员变量会长期占用内存。

8.5封装：不是加 getter 就完事

封装的目的是控制状态如何被修改，而不只是把字段藏起来。

很多教程把封装讲成「字段加 private，再生成 getter/setter」，这其实只做了形式。真正的封装是：对象自己保证内部状态始终合法。比如余额不能被外部直接改成负数，密码不能被读出来，年龄不能是 -5。

做法是把字段设为 private，只暴露必要的方法，并在方法里做校验。对于「只读」字段只提供 getter，对于「可写」字段在 setter 里判断合法性。对于像「存款」这种带业务语义的操作，应该提供 deposit 而不是 setBalance——因为前者能保证「加钱」这个动作的完整性。

封装带来的保护java
private double balance;

public void deposit(double amount) {
    if (amount <= 0) throw new IllegalArgumentException("金额必须大于 0");
    balance += amount;
}

public double getBalance() { return balance; }   // 只读，无 setter
修饰符本类同包子类任意位置
private✓✗✗✗
默认（不写）✓✓✗✗
protected✓✓✓✗
public✓✓✓✓

使用原则很简单：能用 private 就用 private，确实需要对外才放宽。字段一律 private，方法按需 public。暴露得越少，以后改动时受影响的代码就越少。

8.6JavaBean：一套被框架依赖的约定

它不是语法要求，而是生态约定——很多框架靠它工作。

规范有四条：类是 public 的、有无参构造器、字段 private、每个字段配 getter/setter。boolean 类型的 getter 叫 isXxx()，这是命名约定，不能写成 getActive。

为什么框架依赖它？因为 Spring 注入、MyBatis 映射、JSON 序列化都靠反射：它们不知道你的类长什么样，只能按约定去找 setXxx 或 getXxx。字段名是 username，就会去找 setUsername；找不到就赋不上值。

IDEA 一键生成

类中按 Alt + Insert，选择 Constructor、Getter and Setter、toString、equals and hashCode，可以一次性生成全部样板代码。Lombok 的 @Data 也能达到同样效果，但团队要统一使用。

8.7static：属于类，而不是属于对象

加了 static，这份数据或方法就全类共享一份。

普通成员变量每个对象一份，改了不影响别人。加了 static 之后，变量属于类本身，随类加载而初始化，所有对象共用同一份。所以它适合表达「与具体对象无关」的东西：常量、计数器、工具方法。

静态计数器java
public class User {
    private static int count = 0;   // 全类共享

    public User() { count++; }      // 每 new 一个就 +1

    public static int getCount() { return count; }
}

使用上有三条铁律：静态方法不能访问实例成员（没有 this，不知道操作哪个对象）；静态方法里不能用 this / super；静态成员建议用类名访问（User.getCount()），而不是通过对象（user.getCount()），后者会让读代码的人误以为它和对象有关。

还有一点容易被忽略：static 方法不能被重写。子类可以定义同名同参的静态方法，但那叫「隐藏」，调用哪个取决于变量的编译期类型，不参与多态。所以工具类方法适合 static，需要多态扩展的方法不适合。

8.8代码块与 main：谁先执行

顺序是「静态 → 实例 → 构造器」，父类永远先于子类。

静态代码块在类加载时执行，且只执行一次，适合做全局初始化（加载配置、注册驱动）。实例代码块在每次 new 时执行，且先于构造器，适合把多个构造器共用的初始化逻辑抽出来。局部代码块只是限定变量作用域，实际很少用。

执行顺序java
static { System.out.println("1 静态块，只一次"); }
{ System.out.println("2 实例块，每次 new"); }
public Demo() { System.out.println("3 构造器"); }

// 输出：1 2 3 2 3（创建两个对象）

main 方法的五个部分也各有原因：public 是因为 JVM 要从外部调用；static 是因为调用时还没有对象；void 是因为返回值给 JVM 没有意义；名字 main 是约定；String[] args 用来接收命令行参数。少一个修饰符，JVM 就找不到入口。

8.9包、可变参数与递归

包解决重名，可变参数解决「参数个数不定」，递归解决「自己调用自己」。

包的作用类似文件目录：把类分组，避免同名冲突，同时提供一层访问控制（默认修饰符的类只在同包可见）。包名用域名倒写，全小写，例如 com.itheima.demo。使用其他包的类需要 import，同包的类不用。

可变参数 int... nums 本质是数组，必须是参数列表的最后一个，一个方法只能有一个。调用时既可以传多个值，也可以传一个数组，不传则得到长度为 0 的数组（不是 null）。

递归的核心是出口 + 缩小规模。没有出口就会不断压栈，最终 StackOverflowError。写递归前先想清楚：什么时候停？每一步如何让问题变小？想清楚这两点，代码自然就出来了。

递归求阶乘java
public static long factorial(int n) {
    if (n <= 1) return 1;          // 出口
    return n * factorial(n - 1);   // 规模缩小
}

小结这一章真正要记住的

Key takeaways

  1. 类描述「有哪些属性和行为」，对象是它的实例。 每个对象的属性独立，方法共享一份。
  2. 构造器的职责是把对象初始化成合法状态。 手写构造器后，默认无参构造不再自动生成。
  3. this 指向当前对象，用来区分同名变量、复用构造器、链式调用。 static 方法里没有 this。
  4. 成员变量随对象活在堆上，局部变量随方法活在栈上。
  5. 封装的本质是控制状态如何被修改，不是生成 getter/setter。
  6. JavaBean 是框架依赖的约定。 反射按 getXxx/setXxx 找字段，所以命名必须规范。
  7. static 属于类，随类加载初始化，全类共享一份。 不能被重写，不能访问实例成员。
  8. 执行顺序：静态块 → 实例块 → 构造器，父类先于子类。
  9. 递归必须有出口，且每步让规模变小。

自测检查一下你真的懂了吗

只写了有参构造器，还能用 new Student() 吗？为什么框架要求无参构造器？
不能。默认无参构造器只在「完全没有构造器」时由编译器添加。框架（Spring、MyBatis、JSON 库）通过反射 newInstance() 创建对象，必须有可访问的无参构造器。
为什么 setter 里要做校验，而不是把字段设为 public？
public 字段无法阻止非法赋值，对象状态会失控；setter 可以在赋值前校验、转换、触发副作用，并在不改变调用方代码的前提下修改内部实现——这是封装的核心价值。
静态方法里为什么不能用 this？能访问实例变量吗？
静态方法属于类，调用时可能根本没有对象，所以没有 this；同理不能直接访问实例变量/方法，必须先创建对象再通过对象访问。
说出 new 一个对象时的执行顺序。
类加载（首次）→ 静态代码块 → 分配内存并给成员变量默认值 → 实例代码块 → 构造器 → 返回引用。若有父类，父类的静态块、实例块、构造器都先于子类。
可变参数在方法内部是什么类型？调用时一个都不传会得到 null 吗？
本质是数组（int[]），可以直接用 length 和增强 for 遍历。不传参数时得到长度为 0 的数组，不是 null，所以可以直接遍历。
