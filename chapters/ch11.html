常用 API 与 Lambda： 写更现代的 Java

数组长度固定，于是有了集合；匿名内部类太啰嗦，于是有了 Lambda；控制台太单调，于是有了 GUI。这一章把「能装数据的容器」「能传递行为的语法」「能看见的界面」一次补齐。

约 70 分钟 5 个知识点 3 组概念对比 前置：第 10 章

学完这一章，你应该能够

  • 说清集合相对数组的三个优势
  • 正确地在遍历中删除元素
  • 把匿名内部类改写成 Lambda
  • 用四种方法引用简化代码
  • 为窗口选择合适的布局管理器
  • 为按钮绑定点击事件

11.1ArrayList：会自动变长的数组

它不是新数据结构，而是对数组的一层封装。

数组最大的限制是长度固定。ArrayList 的做法很朴素：内部维护一个 Object 数组，装不下时新建一个更大的（约 1.5 倍），把元素复制过去，再让内部引用指向新数组。所以你用的还是数组，只是「扩容」这件事被自动化了。

对比项数组ArrayList
长度固定动态扩容
元素类型基本类型 + 引用类型只能是引用类型（泛型）
功能只能靠下标增删改查、查找、排序都有
性能随机访问最快尾部追加快，中间插入/删除慢

常用方法可以按「增删改查」四类记：add 追加或插入、remove 按对象或按下标删除、set 修改指定位置、get / size / contains / indexOf 查询。注意 remove(1) 删的是下标 1，remove(Integer.valueOf(1)) 删的才是元素 1——这是重载带来的经典歧义。

基本操作java
ArrayList<String> names = new ArrayList<>();
names.add("张三");
names.add(0, "李四");      // 插入到指定位置
names.set(0, "王五");      // 修改
names.remove("张三");      // 按内容删除

for (String n : names) System.out.println(n);
遍历时删除会抛异常

用 for-each 遍历并 remove，会抛 ConcurrentModificationException。因为迭代器维护了一个「修改计数」，集合结构被改动后计数不一致，就立刻报错（fail-fast 机制）。正确做法有三种：用 Iterator.remove()、用 removeIf()、或倒序按下标删除。

为什么设计成「立刻报错」而不是「默默出错」？因为并发修改的结果不可预期：可能漏掉元素、可能越界。fail-fast 让问题在第一次发生时暴露，而不是等到数据错乱才追查。

11.2Lambda：把行为当作参数

它的出现不是为了少写几个字，而是为了让「传递一段逻辑」变得自然。

在 Lambda 之前，想把「一段行为」传给方法，只能写匿名内部类。比如给列表排序，要写六行样板代码，真正的比较逻辑只占一行。Lambda 把「方法签名 + 方法体」压缩成 (参数) -> 表达式，噪声被去掉，意图凸显出来。

同一个逻辑的三次简化java
// 1 匿名内部类
list.sort(new Comparator<String>() {
    @Override public int compare(String a, String b) { return a.length() - b.length(); }
});

// 2 Lambda
list.sort((a, b) -> a.length() - b.length());

// 3 方法引用 + 工具方法
list.sort(Comparator.comparingInt(String::length));

使用 Lambda 有一个硬条件：目标类型必须是函数式接口——有且仅有一个抽象方法的接口。因为编译器要靠「唯一那个抽象方法」推断参数类型和返回值，方法多了就无从推断。JDK 内置了常用的几个，记住它们就能覆盖大部分场景。

接口抽象方法语义
Runnablevoid run()无参无返回的任务
Supplier<T>T get()无参有返回，提供值
Consumer<T>void accept(T)消费一个值，无返回
Function<T,R>R apply(T)一进一出，类型转换
Predicate<T>boolean test(T)条件判断

Lambda 捕获外部局部变量时有一条限制：变量必须是 final 或「事实上不再修改」。原因很实际——Lambda 可能在另一个线程延后执行，如果变量还能改，执行时看到的值就和创建时不一致了。编译器干脆禁止这种不确定性。

11.3方法引用：Lambda 的再简化

当 Lambda 只是「原样调用某个已有方法」时，可以连参数都不用写。

方法引用用 :: 表示，共有四种形式。类名::静态方法，如 Integer::parseInt；对象::实例方法，如 System.out::println；类名::实例方法，第一个参数作为调用者，如 String::length；类名::new，构造器引用。

四种方法引用java
Function<String, Integer> f1 = Integer::parseInt;   // 静态
Consumer<String> f2 = System.out::println;          // 对象实例
Function<String, Integer> f3 = String::length;      // 类实例
Supplier<ArrayList<String>> f4 = ArrayList::new;    // 构造器

什么时候该用？标准是：Lambda 体只有一行，且这一行只是调用一个方法、没有额外逻辑。如果还要做判断、拼接、多次调用，就老老实实写 Lambda，可读性比短更重要。

11.4GUI：组件树与布局管理器

Swing 的界面是一棵树，布局管理器决定每个节点占多大地方。

一个窗口（JFrame）里可以放多个组件（按钮、文本框、标签），组件也可以放进面板（JPanel），面板再放进窗口——层层嵌套形成组件树。每个容器都有一个布局管理器，负责计算子组件的位置和大小。

布局排列规则典型用途
FlowLayout从左到右，满行换行（JPanel 默认）按钮组、工具栏
BorderLayout分东南西北中五区（JFrame 默认）主界面框架
GridLayout规则网格，每格等大计算器键盘、登录表单
BoxLayout单行或单列，可设间距纵向表单
null手动 setBounds，绝对定位固定尺寸的小游戏

实际界面几乎不会只用一种布局，而是组合：外层用 BorderLayout 分出顶部标题栏和中间内容区，中间放一个 GridLayout 面板承载表单。理解「容器可以嵌套、每层各自布局」，就能搭出任何界面。

一个最小窗口java
JFrame frame = new JFrame("登录");
frame.setSize(360, 240);
frame.setLocationRelativeTo(null);              // 居中
frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
frame.setLayout(new GridLayout(3, 2, 10, 10));

frame.add(new JLabel("用户名："));
frame.add(new JTextField());
frame.setVisible(true);                          // 必须最后调用

setVisible(true) 要放在最后，因为它会触发界面绘制。先显示再添加组件，可能出现组件未渲染或界面闪烁。

11.5事件监听：观察者模式

组件是事件源，监听器是观察者，用户操作触发回调。

Swing 的事件模型是标准的观察者模式：你给按钮注册一个监听器，用户点击时，按钮负责调用监听器的方法，并把事件对象传进去。这样组件不需要知道点击后要做什么，业务逻辑完全解耦——同一个按钮可以被注册多个监听器，也可以随时更换。

监听器的本质是接口实现，所以匿名内部类和 Lambda 都能写。ActionListener 只有一个抽象方法 actionPerformed(ActionEvent e)，属于函数式接口，因此可以简写成 e -> { ... }。

点击计数器java
int[] count = {0};                    // 数组绕过 Lambda 的 final 限制
JLabel label = new JLabel("点击：0");

JButton btn = new JButton("+1");
btn.addActionListener(e -> {
    count[0]++;
    label.setText("点击：" + count[0]);
});

这段代码暴露了一个实际限制：Lambda 不能修改外部局部变量，所以计数器只能用数组或成员变量来「绕过」。更规范的做法是把状态放到类的成员变量里，而不是用数组这种小技巧。

Swing 是单线程模型

所有界面更新都必须在事件分发线程（EDT）中执行。启动时用 SwingUtilities.invokeLater(...) 创建窗口，耗时操作要放到后台线程，否则界面会卡死。这是桌面开发与 Web 开发最大的思维差异之一。

小结这一章真正要记住的

Key takeaways

  1. ArrayList 是「会自动扩容的数组」。 尾部追加快，中间插入/删除慢。
  2. 遍历时不能直接 remove。 用 Iterator.remove、removeIf 或倒序下标。
  3. Lambda 只能用于函数式接口。 它的价值是让「行为」可以像数据一样传递。
  4. 捕获的局部变量必须 effectively final。 因为它会被复制进匿名对象。
  5. 方法引用只适用于「原样调用一个方法」。 有额外逻辑就用 Lambda。
  6. 界面是组件树 + 分层布局。 没有一种布局能包打天下，靠嵌套组合。
  7. 事件监听是观察者模式。 组件只负责通知，业务逻辑在监听器里。

自测检查一下你真的懂了吗

ArrayList 能存 int 吗？new ArrayList<int>() 为什么报错？
不能直接存。泛型参数必须是引用类型，应写 ArrayList<Integer>，添加 int 时会自动装箱。
为什么 for-each 遍历时 remove 会抛 ConcurrentModificationException？
for-each 底层用 Iterator，集合结构变化后 modCount 与迭代器的 expectedModCount 不一致，触发 fail-fast 检查。应使用 Iterator.remove()、removeIf() 或倒序下标删除。
Lambda 能用在任何接口上吗？条件是什么？
不能，只能用于函数式接口：有且仅有一个抽象方法（可以有 default / static 方法）。可用 @FunctionalInterface 让编译器校验。
String::length 属于哪种方法引用？等价的 Lambda 是什么？
类名::实例方法引用，等价于 s -> s.length()。第一个参数作为方法调用者，适合「一进一出」的 Function 场景。
JFrame 默认布局是什么？界面复杂时该怎么组织？
默认 BorderLayout。复杂界面靠嵌套：外层用 BorderLayout 划分区域，内部再放使用 GridLayout 或 FlowLayout 的 JPanel，逐层细化。
