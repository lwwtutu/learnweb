Java 入门： 先把世界观建立起来

学 Java 的第一件事不是敲代码，而是搞清楚它为什么能跑：源码怎么变成字节码，字节码又怎么被 JVM 翻译成机器指令。这条链路想通了，后面所有「环境问题」「找不到主类」都不再是玄学。

约 45 分钟 7 个知识点 阅读 + 少量验证 前置：无

学完这一章，你应该能够

  • 说清 JDK / JRE / JVM 的包含关系
  • 解释「一次编译，到处运行」的原理
  • 独立安装 JDK 并验证环境
  • 读懂一个 Java 程序的最小结构
  • 按规范写注释与命名
  • 正确声明变量与字面量

1.1先认识这套工具链

JDK、JRE、JVM 不是三个并列的东西，而是三层套娃。

Java 从诞生起就带着一个野心：同一份程序，不改一行代码，就能在 Windows、Linux、macOS 上运行。这件事在 C/C++ 时代是很难的——因为每种操作系统能执行的机器指令不同，源码必须针对每个平台重新编译。

Java 的做法是插入一层「中间人」：编译器不直接生成机器码，而是生成一种与平台无关的字节码（.class）；真正执行时，由各平台自己的 JVM（Java 虚拟机）把字节码翻译成本平台的机器指令。

写一次，编译一次，剩下的翻译工作交给每个平台自己的 JVM。
三个缩写的分工

JVM（Java Virtual Machine）是执行字节码的虚拟计算机，负责类加载、内存管理、垃圾回收、指令翻译。它不认识 .java 文件，只认识 .class。

JRE（Java Runtime Environment）= JVM + 核心类库。它只能运行已经编译好的程序，不能编译源码。给最终用户装的就够了。

JDK（Java Development Kit）= JRE + 编译器 javac + jar、javadoc、jconsole 等开发工具。开发者必须装它。

名称包含什么能做什么谁需要
JDKJRE + javac + 开发工具编写、编译、运行、调试开发者
JREJVM + 核心类库只能运行 .class终端用户
JVM类加载器、执行引擎、运行时数据区把字节码翻译成机器指令由 JRE/JDK 自带

所以「学 Java 要装什么」这个问题只有一个答案：装 JDK。装了 JDK，JRE 和 JVM 自然都在里面。版本上建议直接用 LTS（长期支持版），目前主流是 17 和 21，本手册的示例都可以在这两个版本上运行。

安装完还要配一个环境变量 JAVA_HOME，并把 %JAVA_HOME%\bin 加进 Path。这一步的意义是：让命令行在任何目录下都能找到 javac 和 java 这两个可执行文件。配好后用两条命令互相验证——它们必须是同一个版本：

命令行验证shell
java -version
javac -version
为什么会出现「java 能用、javac 不能用」

说明 Path 里指向的是 JRE 的 bin 目录，或者机器上装过多个 Java、旧路径排在前面。解决办法是把 %JAVA_HOME%\bin 挪到 Path 最前面，再开一个新的命令行窗口（旧窗口不会重新读环境变量）。

1.2一个 Java 程序的最小结构

六行代码，包含了 Java 程序的全部骨架要素。

先不谈语法细节，看清楚这个结构由哪几层组成：最外面是类，类是 Java 组织代码的基本单位，任何代码都必须写在类里面；类里面是方法，方法里才是真正干活的语句。

HelloWorld.javajava
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}

逐层理解：

  • public class HelloWorld：声明一个公开的类，名字叫 HelloWorld。这个文件名必须叫 HelloWorld.java，大小写都要一致。
  • public static void main(String[] args)：主方法，是整个程序的唯一入口。JVM 启动后第一件事就是找它，格式一个字都不能错。
  • System.out.println(...)：向控制台输出一行内容并换行。它是「调用对象的方法」，不是关键字，所以后面有括号。
为什么 main 的格式是固定的

因为调用它的是 JVM，不是你自己写的代码。JVM 不读你的注释、不理解你的意图，它按约定去找「公开的、静态的、无返回值、参数是字符串数组、名字叫 main」的方法。少一个修饰符，它就找不到入口，于是报「找不到或无法加载主类」。

另外三个新手高频错误也来自同一类原因——Java 对拼写和大小写极其严格：类名写成 main 小写、文件名与类名不一致、语句末尾用了中文分号，都会直接编译失败，而不是「大概能跑」。

1.3代码是怎样跑起来的

javac 负责翻译，java 负责启动 JVM，两件事分工明确。

写好的 .java 文件只是文本，机器不认识。第一步用 javac 编译，得到 .class 字节码文件；第二步用 java 命令启动 JVM，由它加载并执行字节码。注意运行时不带 .class 后缀，写的是类名：

编译与运行shell
javac -encoding UTF-8 HelloWorld.java   # 生成 HelloWorld.class
java HelloWorld                          # 启动 JVM 执行

完整链路由四步构成，每一步都有明确的产物和责任人：

  1. 编写

    产出 .java 源文件，本质是 UTF-8 或 GBK 编码的纯文本。

  2. 编译

    javac 做语法检查、类型检查，产出与平台无关的 .class 字节码。语法错误在这一步就会被拦下。

  3. 加载

    java 命令启动 JVM，类加载器把 .class 读进内存，完成链接与初始化。

  4. 执行

    执行引擎把字节码翻译成机器指令。热点代码会被 JIT 编译成本地代码以提升性能。

理解了这条链，就能解释很多现象：为什么改了代码不重新编译、运行结果还是旧的；为什么别人给你一个 .class 你能直接跑；为什么同一个程序在 Mac 上也能跑——因为字节码是统一的，差异全部由 JVM 吸收。

中文乱码的根源

Windows 命令行默认按 GBK 解码，而源码通常存成 UTF-8，两边不一致就出现乱码。编译时加 -encoding UTF-8，或统一把编辑器和编译参数都设为 UTF-8，问题就消失了。

1.4在 IDEA 里工作

IDE 没有替你跳过上面的流程，只是把它自动化了。

IntelliJ IDEA 的项目结构是四层：Project（工程）→ Module（模块）→ Package（包）→ Class（类）。源码放在 src 下，包名用点分层级，例如 com.itheima.hello 对应目录 src/com/itheima/hello。你点绿色三角运行时，IDEA 在背后做的就是「调用 javac 编译到 out 目录，再用 java 启动对应类」。

刚上手不必记几十个快捷键，先记住这六个，效率就能翻倍：

快捷键作用什么时候用
psvm + Tab生成 main 方法新建测试类
sout + Tab生成输出语句调试变量
Ctrl + D复制当前行写重复结构
Ctrl + Alt + L格式化代码提交/分享前
Alt + Enter快速修复、导包出现红色波浪线时
Shift + F6重命名改变量名，连带引用一起改

还有一个习惯值得从第一天就建立：类名、变量名用英文，不要用拼音；包名全小写。这不是形式主义，而是因为 Java 的类名会直接变成文件名和目录结构，中文和空格会在某些工具链上引发难以排查的问题。

1.5注释：写给人的那部分

注释不参与编译，但它决定了代码能不能被维护。

Java 有三种注释，用途完全不同，不要混用：

形式写法用途
单行注释// 说明解释某一行或某一段逻辑
多行注释/* ... */临时注释掉一段代码，或写较长的说明
文档注释/** ... */配合 @param、@return 生成 API 文档
注释示例java
/**
 * 计算两个整数的和
 * @param a 加数
 * @param b 被加数
 * @return 两数之和
 */
public static int add(int a, int b) {
    return a + b;   // 单行注释：放在语句右侧
}

写注释有一条实用标准：解释「为什么」，而不是复述「做了什么」。// 把 i 加 1 毫无价值，// 跳过表头行，从第二行开始解析 才有价值。另外，多行注释不能嵌套，/* /* */ */ 会在第一个 */ 处提前结束，导致后面的代码被当成源码而报错。

文档注释的实际用途

在项目根目录执行 javadoc -d doc src/*.java，就能把 /** */ 里的内容生成一套 HTML 格式的 API 文档——你平时查的 JDK 官方文档就是这么来的。

1.6变量：给内存起个名字

变量的本质，是一块被命名的内存空间，类型决定这块空间有多大。

程序运行时要处理数据，数据得放在内存里。你没法直接对着「地址 0x7ffe3a」读写，所以语言提供了变量：给它起个名字，通过名字访问那块空间。声明变量时写的类型，就是告诉编译器「按这个规格给我划一块地」。

变量的三要素

数据类型：决定空间大小、能存什么、能做哪些运算。
变量名：合法的标识符，是访问这块空间的唯一凭据。
值：空间里当前存放的内容，必须与类型匹配，且使用前必须存在。

声明与赋值java
int age = 18;              // 声明并赋值
double score = 92.5;       // 小数用 double
char level = 'A';          // 单个字符用单引号
boolean pass = true;       // 只有 true / false
String name = "张三";       // String 是引用类型，双引号

age = 19;                  // 重新赋值：类型不变，值可改

Java 的八种基本类型可以先用「够不够用」来判断：整数默认 int（约 ±21 亿），小数默认 double，单个字符用 char，真假用 boolean；只有时间戳、超大整数才用 long（记得加 L），精度要求不高的小数才用 float（记得加 f）。完整的取值范围下一章会展开。

这里先记住两条硬规则：① 局部变量必须先赋值再使用，成员变量才有默认值；② 变量名区分大小写，age 和 Age 是两个完全不同的变量。

0.1 + 0.2 != 0.3

这不是 Java 的 bug，而是二进制浮点的固有特性：0.1 在二进制中是无限循环小数，只能近似存储。涉及金额计算时不要用 double，改用 BigDecimal（第 07 章会讲）。

1.7字面量与标识符

字面量是「直接写出来的值」，它的写法决定了编译器如何理解它。

同一个数字，写法不同，编译器给它的类型就不同。100 是 int，100L 是 long，100.0 是 double，100.0f 是 float。类型一旦确定，能参与的运算和赋值目标就确定了，所以字面量后缀不是装饰，而是类型声明。

字面量写法要点
整数100、1_000_000默认 int，下划线只是分隔符，编译时忽略
其他进制0b1010、010、0x1F分别是二进制 10、八进制 8、十六进制 31
长整型10000000000L超出 int 范围必须加 L，否则编译报错
小数3.14、2.7f默认 double；float 必须加 f
字符'A'、'\n'、'\u0041'单引号，只能一个字符，可用转义
字符串"Hello"、""双引号，可以是空串
布尔true / false不能用 1 / 0 代替
字面量写法java
System.out.println(0b1010);      // 10
System.out.println(0x1F);        // 31
System.out.println("他说：\"你好\"");   // 转义双引号
System.out.println("D:\\code");     // 转义反斜杠

与字面量配套的是标识符——你给类、方法、变量起的名字。规则只有四条：由字母、数字、下划线、美元符组成；不能以数字开头；不能是关键字（class、int、public 等）；区分大小写。命名风格上，类名用大驼峰 StudentManager，变量和方法用小驼峰 totalScore，常量全大写 MAX_SIZE。

char 与 String 不能互换

'A' 是 char（本质是一个 16 位整数，值为 65），"A" 是 String（对象）。char c = "A"; 编译报错，因为类型不兼容。这是初学者最常犯的类型错误之一。

小结这一章真正要记住的

Key takeaways

  1. JDK 包含 JRE，JRE 包含 JVM。 开发只装 JDK，配置 JAVA_HOME 是为了让命令行找到 javac 和 java。
  2. Java 的执行链路是「源码 → 字节码 → JVM 翻译 → 机器码」。 字节码与平台无关，跨平台能力来自各平台的 JVM。
  3. 一个程序的结构是「类 → 方法 → 语句」。 main 是 JVM 约定的入口，格式固定，不能改名改参数。
  4. public 类名必须与文件名完全一致。 大小写、拼写、分号，任何一处不一致都会编译失败。
  5. 注释解释「为什么」，命名表达「是什么」。 好的代码靠命名自解释，靠注释补充意图。
  6. 变量是命名的内存空间，类型决定空间大小。 局部变量必须先赋值；小数默认 double，float 要加 f。

自测检查一下你真的懂了吗

JDK、JRE、JVM 的包含关系是什么？只装 JRE 能不能编译 Java 代码？
JDK ⊃ JRE ⊃ JVM。JRE 只有运行环境，没有 javac，所以只能运行已有的 .class，不能编译 .java 源码。
为什么说 Java 是「一次编译，到处运行」？这个能力由谁提供？
javac 生成的是与平台无关的字节码，各平台安装自己的 JVM，由 JVM 把字节码翻译成本平台的机器指令。跨平台能力由 JVM 提供，代价是需要为每个平台维护一套 JVM。
下面这段代码能编译通过吗？public class Demo { } 保存为 demo.java。
不能。public 类的类名必须与文件名完全一致（含大小写），会报「should be declared in a file named Demo.java」。
System.out.println(1 + 2 + "3") 与 System.out.println("1" + 2 + 3) 分别输出什么？
第一个输出 33：先算 1+2=3，再与字符串拼接；第二个输出 123：从左到右，遇到字符串后后面的都按拼接处理。
为什么 long time = 1700000000000; 会报错？怎么改？
整数字面量默认是 int，该值超出 int 上限（约 21 亿）。改为 1700000000000L，加 L 表示 long 字面量。
