### 三目的三段结构

三目运算符写作 `条件 ? A : B`：条件成立取 `A`，否则取 `B`。问号与冒号把式子分成条件、真分支、假分支三段，缺一段都不完整。

它叫"三目"，正因为要同时处理三个操作数。只有 `?` 没有 `:` 会直接抛语法错误，因为解析器找不到假分支去取值。

```js
var sum = 190
var pay = sum > 200 ? sum - 10 : sum   // => 190
var label = 1 > 2 ? "大" : "小"        // => "小"
```

> ⚠️ `?` 与 `:` 必须成对出现，三段缺一不可。

### 表达式与语句的本质区别

同样二选一给变量赋值，`if...else` 要写好几行，三目一行就能算出结果。但真正的差别不在长短，而在两者的身份。

`if` 是语句，只执行动作、不产出值；三目是表达式，一定会算出一个值。因此三目能直接放在赋值号右边，`if` 不能。

```js
var a
if (1 > 2) { a = "大" } else { a = "小" }   // 语句：先做事，再赋值
var b = 1 > 2 ? "大" : "小"                 // => "小"
```

写成 `var b = if (...) {...}` 是语法错误，因为语句没有值可以赋出去。

### 什么时候用三目，什么时候用 if

判断标准来自"要的是值还是动作"：只二选一取一个值用三目；要执行多条语句、改多个变量，或分支超过两个，就该用 `if`。

嵌套三目很难读，硬把多件事塞进逗号表达式虽能跑，却牺牲了可读性，并不划算。

| 场景 | 选谁 | 原因 |
|---|---|---|
| 二选一取一个值 | 三目 | 直接产出值 |
| 执行多条语句 | if | 语句块更清晰 |
| 分支超过 2 个 | if...else if | 避免嵌套 |
| 多次打印、改多个变量 | 一般用 if | 有副作用 |

可见二选一取一个值，才是三目真正的主场。

### 嵌套三目与实用场景

多档满减可以嵌套三目，第二个三目务必加括号。三目是右结合的，多层嵌套会先算最右边那组，加括号就不必去记结合方向。

嵌套建议最多两层，三层以上改用 `if...else if`，否则一周后自己都看不懂。三目可以跨行写，因为 JS 对换行不敏感。

```js
var sum2 = 150
var price = sum2 > 200 ? sum2 - 10 : (sum2 > 100 ? sum2 - 5 : sum2)  // => 145
```

150 不满足满 200，进入内层满足满 100，减 5 得 145。

> 💡 默认值、状态文案、class 名、判断奇偶、取两数较大值，都是三目的典型用法。

### 单分支 if：条件成立才执行

此前代码都自上而下顺序执行，而现实需求常是"如果……就……"，分支结构因此出现。

`if (条件) { ... }` 只在条件为真时进入花括号；为假时整段跳过，程序继续往下走，什么也不做。条件位可以是任意表达式，JS 会先把结果转成布尔值再判断。

```js
if (true)  { console.log("会执行") }    // => 会执行
if (false) { console.log("不会执行") }  // 无输出
```

结果是条件为真那行才打印，为假那行静默跳过。

### 双分支 if...else：两条路必走一条

`if...else` 给条件为假时补了一条去路，两个花括号一定执行一个、且只执行一个，适合非此即彼的判断。

判断奇偶用 `n % 2 === 0` 最清楚。虽然 `if (n % 2)` 靠真值也能写，但意图不如显式比较直观，新手阶段建议用前者。

```js
var n = 9
if (n % 2 === 0) {
    console.log("偶数")
} else {
    console.log("奇数")   // => 奇数
}
```

> ⚠️ `else` 不能单独出现，必须紧跟在某个 `if` 后面。

### 多分支与命中即停

`if...else if...else` 把多个条件从上往下依次判断，末尾用 `else` 兜底。最核心的规则是"命中即停"。

一旦某个条件成立，执行完它的花括号后整条链就结束，后面条件不再看。因此区间判断要按范围从大到小排，每个条件只写下限即可，能走到这里说明前面的都没成立。

| 条件顺序 | score = 85 的结果 |
|---|---|
| 先判 `>= 90` 再判 `>= 80` | 命中 B，正确 |
| 先判 `>= 60` 再判 `>= 90` | 命中 D，A 永远到不了 |

把非法输入用"卫语句"挡在最前面，末尾用 `else` 兜底，保证任何输入都有输出。

### 嵌套、else 归属与花括号

`if` 里可以再套 `if`，但 `else` 永远归属离它最近、且尚未配对的那个 `if`，与缩进无关，这就是"悬空 else"问题。

只有一句代码时花括号可省，可一旦省略，`else` 的配对就容易看错——缩进会骗人，而 JS 只认 `{}`。所以花括号永远不省，用括号把归属写死最稳妥。

```js
var year = 2000
// && 优先级高于 ||，复合条件一律加括号
var leap = year % 400 === 0 || (year % 4 === 0 && year % 100 !== 0)
console.log(leap)                    // => true
console.log(true || false && false)  // => true
```

判断闰年的复合条件尤其要小心：`&&` 优先级高于 `||`，若从左往右硬算会得到相反结论。

lessons: 021–022
summary: switch 适合一个值匹配固定选项，内部用严格相等，break 决定是否穿透
points: switch 适合一个值匹配固定选项，区间判断用 if || 内部比较是严格相等，字符串与数字不会匹配 || case 后只能写具体值，不能写比较表达式 || 漏写 break 会触发穿透，一路执行到下一个 break || 多个 case 共享逻辑是有意穿透，可省重复代码
===BODY===
### 语法与解决的问题

`switch` 专为"一个值匹配多个固定选项"而生，如状态码、星期、月份，这类需求最适合等值判断。

这类需求写成一长串 `else if (code === ...)` 会很啰嗦。`switch` 把被判断的值写在括号里，用 `case` 列候选、`default` 兜底，结构更整齐。

```js
var code = 3
switch (code) {
    case 1: console.log("未付款"); break
    case 2: console.log("已付款"); break
    case 3: console.log("已发货"); break   // => 已发货
    default: console.log("出错了")
}
```

命中后从该 `case` 往下执行，直到 `break` 或结束。

### 三条必须记住的规则

`switch` 内部用严格相等 `===` 比较，且 `case` 后只能写具体的值，不能写比较表达式。

`"3" === 3` 为假，所以 `input`、`prompt` 取到的字符串直接判断会失效，需先 `Number()` 转换；`case sum > 100` 会被算成 `true`/`false`，几乎永远匹配不上。

| 规则 | 说明 | 后果 |
|---|---|---|
| 严格相等 `===` | 值与类型都要相同 | `"3"` 匹配不上 `3` |
| case 后只能写值 | 不能写比较表达式 | `case sum > 100` 恒不匹配 |
| break 不能漏 | 否则向下穿透 | 执行后面所有 case |

反过来用 `parseInt(score / 10)` 把区间压成整数，就能转成等值判断。

### break 穿透：是坑也是工具

漏写 `break` 会触发 case 穿透，从命中的 `case` 一路执行到下一个 `break` 为止。

这是 `switch` 的机制而非 bug——找到第一个匹配后本就"一路往下"。用对了能省代码：让多个 `case` 叠在一起、只在最后写逻辑，共享同一段处理。

```js
var month = 2
switch (month) {
    case 1: case 3: case 5: case 7: case 8: case 10: case 12:
        console.log("31天"); break
    case 2:
        console.log("28天"); break   // => 28天
}
```

判断标准只有一条：穿透是"故意共享"还是"忘了写 break"，前者可以，后者必须补。

### switch 与 if 怎么选

两者都能做分支，选谁取决于判断的是"等值"还是"区间"。

一个值对固定选项或状态映射，用 `switch` 更清晰；区间、多个条件组合，用 `if` 更直接。只有两种结果取一个值，三目最简。

| 场景 | 选谁 |
|---|---|
| 一个值匹配固定选项 | switch |
| 判断区间或多个不同条件 | if |
| 只有两种结果、取一个值 | 三目 |

`switch (true)` 配 `case sum >= 200` 虽能做区间，却更啰嗦、可读性差，并不推荐。

lessons: 023–024
summary: while 先判断后执行，四个零件缺一不可，步长遗漏会造成死循环
points: 循环让同一段代码重复执行，不必手写多遍 || 初始化、条件、循环体、自身改变四个零件缺一不可 || 缺了自身改变或步长方向反了会造成死循环 || 累加器按目标给初值，求和为 0、求积为 1 || 次数不确定用 while，次数明确优先用 for
===BODY===
### 语法与执行顺序

要在页面输出 100 个列表项，不可能手写 100 行；循环就是让同一段代码重复执行。

`while` 读作"当条件成立时就一直做"：初始化写在循环外、步长写在循环体内。执行顺序是先判断条件，成立才进循环体，做完回到判断，直到条件为假退出。

```js
var n = 2
while (n < 10) {
    console.log("li", n)   // => 依次 2 4 6 8
    n += 2
}
```

`n` 取 2、4、6、8 各执行一次，变成 10 后 `10 < 10` 不成立而结束，所以结束时 `n` 是 10 而非 8。

### 三要素：初始化、条件、更新

任何循环都靠三要素支撑：初始值定起点、条件定何时停、更新让条件最终变假。三者缺一就出问题，其中更新最容易被漏掉。

| 零件 | 作用 | 缺了会怎样 |
|---|---|---|
| 初始化 | 设定起点 | 变量未定义、结果错 |
| 条件判断 | 决定还继不继续 | 无法终止 |
| 循环体 | 真正要干的事 | — |
| 自身改变（步长） | 让条件最终变 false | 死循环 |

累加器也遵循同一套路：按目标给初值，求和为 0、求积为 1、拼字符串为 ""，因为起点错了后面全错。

> 💡 求阶乘写成 `result *= n` 递减到 0，若初值误写成 0，结果会恒为 0。

### 适用时机

循环次数不确定、要"等某个条件成立"时适合 `while`，因为事先不知道要问几次。

反复要求用户输入直到填对，正是 `while` 的主场；而遍历 1~100、批量生成结构这类定次任务，`for` 把三要素收进一行更不易漏。

| 场景 | 选谁 |
|---|---|
| 次数不确定、等条件成立 | while |
| 次数明确、遍历区间或数组 | for |

`do...while` 则用于"至少执行一次"的场合，三者的差异主要体现在判断时机与最少执行次数上。

### 死循环防范

条件永远为真、循环无法终止，就是死循环，浏览器标签页会直接卡死。

最常见原因是漏写步长、条件写成恒真 `while (true)`，或步长方向反了（该递增却递减）。写 `while` 前先自问"这个条件靠什么变成 false"，能从源头避免。

```js
var n = 2
while (n < 10) {
    console.log(n)
    // 忘了写 n += 2，n 永远是 2 → 死循环
}
```

> ⚠️ 真卡死可用浏览器任务管理器结束进程；`while (true)` 必须靠内部 `break` 留出口才安全。

title: do...while 循环
lessons: 025–026
summary: do...while 先执行一次再判断，循环体至少执行一次，适合必须先取输入的场景
points: while 先判断后执行，do...while 先执行后判断 || do...while 的循环体至少执行一次 || 结尾 while(条件) 后必须加分号 || 必须先取到输入再决定继续时，用它最自然 || prompt 返回字符串或 null，计算前要转数值
===BODY===
### 语法与执行顺序

`while` 先判断后执行，条件一开始为假就一次都不做；`do...while` 先执行一次循环体，再判断条件。

因此 `do...while` 的循环体至少执行一次，这是它与 `while` 唯一却关键的差别。执行流程是"执行 → 判断 → 执行 → 判断…… → 判断为假结束"，判断被放到了末尾。

```js
while (false) {
    console.log("hello")     // 不执行
}
do {
    console.log("hello")     // => hello，执行 1 次
} while (false)
```

`while` 版零输出，`do...while` 版会打印一次 hello。

### 三要素：初始化、条件、更新

写法是 `do { ... } while (条件);`，结尾 `while (条件)` 后必须加分号，因为它表示整条语句到此结束。

三要素同样缺一不可。另一个坑是别漏写开头的 `do`，否则就退化成普通 `while`。计数要数准，因为判断放在末尾，起点和边界很容易差一次。

```js
var n = 0
do {
    n++
} while (n < 10)   // 分号不能省
console.log(n)     // => 10
```

`n = 0` 配 `n < 10` 得到 10 次（0 到 9），配 `n <= 10` 就是 11 次。

### 适用时机

`do...while` 的价值在"第一次必须先干，再决定要不要继续"，最适合先取输入再校验的场景。

例如必须让用户输入名字，不填就一直问。第一次询问前还没有任何输入，`while` 无法先判断；`do...while` 恰好对应"先问，再看结果决定要不要再问"，用 `while` 写就得多复制一遍 `prompt`。

```js
var res
do {
    res = prompt("请输入你的名字")
} while (!res)
console.log(res)    // => 用户输入的名字
```

| 循环 | 判断时机 | 最少执行 | 适用场景 |
|---|---|---|---|
| while | 先判断 | 0 次 | 次数不确定 |
| do...while | 后判断 | 1 次 | 至少执行一次 |
| for | 先判断 | 0 次 | 次数明确，最常用 |

先按"次数是否确定、是否至少一次"两条，就能在三者间快速选型。

### 死循环防范

`do...while` 同样要初始化、条件、更新齐全，漏了更新或条件方向反了照样卡死，因为判断在末尾、更新写在循环体内。

还要留意 `prompt` 的返回值：输入内容是字符串（空串也算），点取消是 `null`，拿到的永远是字符串，参与计算前要用 `Number()` 或 `parseFloat()` 转换。

> ⚠️ 次数确定时 `do...while` 与 `while` 结果一致，都会让位给 `for`；它只在"至少一次"场景不可替代。

title: for 循环
lessons: 027–028
summary: for 把循环四零件收进一行，执行顺序固定，是次数明确时的首选写法
points: for 把三个零件收进括号，是 while 的整理版 || 初始化只执行一次，步长在循环体之后执行 || 循环结束后计数变量仍保留退出时的值 || 累加器要放在循环外，放进循环会被每轮重置 || 次数公式 (末尾-起始)/步长+1，< 与 <= 差一次
===BODY===
### 语法与执行顺序

`for (初始化; 条件; 自身改变)` 把 `while` 分散在三处的三件事归拢到括号里，没有新增功能，只是更不容易漏掉步长。

执行顺序容易想错：初始化只跑一次，然后"判断 → 执行循环体 → 执行 `i++` → 再判断"依次循环。关键是步长在循环体之后执行，所以循环体里拿到的是还没加过的值。

```js
// while：三件事分散
var i = 1
while (i <= 3) {
    console.log(i)   // => 1 2 3
    i++
}

// for：收进一行
for (var j = 1; j <= 3; j++) {
    console.log(j)   // => 1 2 3
}
```

最后一次 `j++` 把 3 变成 4、判断失败才退出，因此循环结束后 `j` 是 4 而非 3。

### 三要素：初始化、条件、更新

`for` 把三要素写得最清楚，累加器必须放在循环外面，否则每轮都被重置、结果只剩最后一个数。

循环里套 `if` 是常态，比如前 3 条标为广告、其余标为普通商品；输出 1000 到 2000 的闰年时，还可把步长改成 4、用计数器每 4 个换行。

```js
var sum = 0
for (var k = 1; k <= 100; k++) {
    sum += k
}
console.log(sum)     // => 5050
```

> ⚠️ 若把 `var sum = 0` 写进循环体，每轮清零，结果只会是 100。

### 适用时机

次数明确时优先用 `for`，因为三要素集中在一行，改范围或步长都不容易遗漏。

`while` 留给次数不确定的等待，`do...while` 留给至少执行一次的输入校验。三者执行逻辑相同，差别主要在写法与最少执行次数。

| 写法 | 次数 |
|---|---|
| `i = 0; i < 10; i++` | 10 次（0~9） |
| `i = 1; i <= 10; i++` | 10 次（1~10） |
| `i = 1; i < 10; i++` | 9 次（1~9） |
| `i = 0; i <= 10; i += 2` | 6 次（0,2,4,6,8,10） |

通用公式是 `次数 = (末尾 - 起始) / 步长 + 1`（能整除时），`<` 与 `<=` 恰好差一次。

### 死循环防范

三个部分都能省略，但 `for (;;)` 等价于 `while (true)`，是写法最简洁也最难读的死循环。

因为省掉了条件，它必须靠内部 `break` 留出口才安全。另外 `var` 没有块级作用域，循环变量在循环外仍可访问，属于历史缺陷，日后换 `let` 就能彻底隔离。

```js
for (;;) {
```

### break：结束整个循环

`break` 让整个循环立即结束，跳到循环外面，后续轮次一次都不再执行。

它适合"找到目标就收工"。在大批量数据里命中后提前退出，能避免无谓空转，因此也是一种常见的性能优化手段。

```js
for (var i = 0; i <= 5; i++) {
    if (i === 3) break
    console.log(i)       // => 0 1 2
}
```

`i = 3` 时收工，4、5 根本没执行。

### continue：只跳过本轮

`continue` 跳过本轮剩下的代码，直接进入下一轮，后续轮次照常执行。

它适合过滤无效数据，比如跳过空值或已删除的脏数据，只让有效项进入处理逻辑。与 `break` 的差别只在影响范围：一个管整个循环，一个管当前一轮。

```js
for (var j = 0; j <= 5; j++) {
    if (j === 3) continue
    console.log(j)       // => 0 1 2 4 5
}
```

只跳过 3，4、5 继续输出。

### 两者的区别

把范围、后续轮次、用途放在一起对照，最不容易把两者记混。

| 对比 | break | continue |
|---|---|---|
| 影响范围 | 整个循环 | 当前这一轮 |
| 后续轮次 | 不再执行 | 继续执行 |
| 常见用途 | 找到目标就收工 | 过滤无效数据 |

> ⚠️ `continue` 用在 `while` 里会跳过写在末尾的 `i++`，变量卡住不动就成死循环。
> 💡 `for` 没这问题，因为步长在括号里、`continue` 跳不到；用 `while` 时应把步长写在判断之前，或改用 `for`。

### 嵌套循环中的 break 与标签

双层循环里 `break` 只跳出当前这一层，外层照常跑完，因为它默认只结束离自己最近的那层循环。

想跳出外层有两种办法：加一个标志位，在内层置位、外层检测后再 `break`；或给循环加标签，用 `break outer` 直接指定跳出哪一层。标志位更通用，标签更直接却难读。

```js
outer:
for (var m = 1; m <= 3; m++) {
    for (var n = 1; n <= 3; n++) {
        if (n === 2) break outer   // 直接跳出外层
        console.log(m, n)          // => 1 1
    }
}
```

若只写 `break` 不带标签，输出会是 `1 1 / 2 1 / 3 1`，因为内层每次被打断、外层仍跑三轮。

### 需求与思路

质数指大于 1、只能被 1 和自身整除的整数。因为任何能整除 n 的数都算约数，所以从 2 起用 `n % i` 逐个试除即可，一旦整除就说明它还有第三个约数。

试除不必走到 n-1：约数成对出现，只需试到平方根，所以循环条件写成 `i * i <= n`，能省掉大量无效判断。

用一个标志位先假设「是质数」，循环里被推翻就置 false 并 break；结束后看标志位下结论，这样「是否被整除」被显式记录，不依赖循环变量。

### 完整案例代码

```js
// 综合案例：判断质数（试除 + 标志位）
function isPrime(n) {
  if (n <= 1) return false          // ← 关键点：边界值先排除，1 既不是质数也不是合数
  var flag = true                   // ← 关键点：标志位记录「是否被整除」
  for (var i = 2; i * i <= n; i++) {  // ← 关键点：循环边界，试除到平方根即可
    if (n % i === 0) {              // ← 关键点：判定条件，取余为 0 即整除
      flag = false
      break
    }
  }
  return flag
}
console.log(isPrime(7))     // => true
console.log(isPrime(71))    // => true
console.log(isPrime(111))   // => false
console.log(isPrime(1))     // => false
```

### 关键知识点

- **试除只需到平方根**：约数总是成对出现（如 36 = 4×9），大的那个必然超过根号 n，所以试到 `i * i <= n` 就够了。换成 `i <= n / 2` 结果也对，但会多跑近一倍无效循环。
- **用标志位记录是否被整除**：先假设 `flag = true`，一旦发现整除就改成 false 并 break。若改用循环变量 i 的终值判断，也能区分「break 结束」和「自然结束」，但那样依赖 var 在循环外仍可访问，换成 let 就会报错，可移植性差。
- **先处理 n ≤ 1**：漏掉这行时，n = 1 会让循环一次都不执行，标志位保持 true 被误判成质数；单独 return false 能堵住这个特例。

title: 综合案例：九九乘法表
lessons: 031
summary: 九九乘法表用双层循环，外层管行内层管列，内层上限随行号变化
points: 外层循环控制行数，内层循环控制每行的列数 || 第几行就有几列，内层上限取外层变量 m || 每行结束后再换行，换行代码放在外层循环体里 || 拼接时乘法优先级高于加号，算式建议加括号 || 同一模型改内层上限就能打印矩形、三角形等图形
===BODY===
### 需求与思路

九九乘法表第 1 行 1 个算式、第 2 行 2 个……第 9 行 9 个，列数正好等于行号，所以「行」和「每行里的列」是两层重复，要用双层循环。

外层管行、内层管列，且内层上限要跟着外层变量走，写成 `n <= m` 才能逐行递增；因为每行只有 m 列，写成固定的 9 就变成矩形了。

一行的所有算式拼完后才换行，所以换行（输出整行）放在外层循环体、内层循环之后。

### 完整案例代码

```js
// 综合案例：九九乘法表，每行拼成一个字符串再输出
for (var m = 1; m <= 9; m++) {               // ← 关键点：外层管行，m 控制第几行
  var line = ""
  for (var n = 1; n <= m; n++) {             // ← 关键点：内层上限随行号变化，n <= m 才逐行递增
    line += m + "*" + n + "=" + (m * n) + " "  // ← 关键点：拼接优先级，乘法先算，算式加括号更清楚
  }
  console.log(line)                          // ← 关键点：换行放在外层，一行拼完再换行输出
  // 页面版本改成 document.write(line + "<br>")，换行位置不变
}
// => 1*1=1
// => 2*1=2 2*2=4
// => 3*1=3 3*2=6 3*3=9
// => 4*1=4 4*2=8 4*3=12 4*4=16
// => 5*1=5 5*2=10 5*3=15 5*4=20 5*5=25
// => …… 依次输出到第 9 行，共 45 个算式
```

### 关键知识点

- **内层上限取行号 m**：第 m 行只有 m 个算式，所以内层写成 `n <= m` 才会逐行递增；换成固定的 9，每行都会打满 9 个，表格变成矩形，规律就没了。
- **换行放在外层**：一行的所有列写完后才该换行，因此换行（输出整行）必须放在外层循环体、内层循环之后；若放进内层，每个算式都单独占一行，表格会竖成一列。
- **拼接注意运算符优先级**：`*` 优先级高于 `+`，所以 `m * n` 会先算成乘积，其余 `+` 都是字符串拼接；一旦前面出现字符串，后面的 `+` 就全变成拼接，给算式加括号 `(m * n)` 最稳妥。
