抽象、接口与内部类： 面向抽象编程

当你说「我需要一个能飞的」，而不是「我需要一只鸟」，你就开始面向接口编程了。抽象类定义模板，接口定义能力，内部类让实现藏得更近——这三者构成了 Java 的扩展机制，也是所有框架的设计语言。

10.1抽象类：把「不确定」留给子类

它描述「是什么」，但有些行为说不清楚，只能要求子类必须实现。

假设要设计图形系统。所有图形都有面积和周长，但「怎么算」完全取决于具体形状——圆的公式和矩形完全不同。这时父类只适合声明「必须能算面积」，而不该给出实现。这种只有声明没有方法体的方法叫抽象方法，含抽象方法的类必须声明为抽象类。

抽象类的两个关键限制：不能实例化（因为它的行为不完整），但可以有构造器（供子类调用）、可以有普通方法、可以有成员变量。它更像一个「半成品」，把确定的逻辑写好，把不确定的留给子类填空。

抽象类与实现类java
public abstract class Shape {
    protected String name;

    public abstract double area();      // 子类必须实现

    public void print() {               // 公共逻辑写一次
        System.out.printf("%s 面积 %.2f%n", name, area());
    }
}

class Circle extends Shape {
    private final double r;
    public Circle(double r) { this.r = r; this.name = "圆"; }
    @Override public double area() { return Math.PI * r * r; }
}

这就是模板方法模式的雏形：父类定义流程骨架（先算面积再打印），把变化的步骤做成抽象方法交给子类。print() 只写一次，所有子类复用；area() 各不相同，各自实现。既避免了重复，又保留了扩展点。

抽象类可以没有抽象方法

一个类即使所有方法都有实现，只要加了 abstract 就不能被实例化。这种用法常见于「工具基类」——目的不是强制子类实现什么，而是禁止直接创建它。但它不能再加 final，因为 final 禁止继承，和 abstract 互相矛盾。

10.2接口：只约定能力，不关心身份

接口回答「能做什么」，而不是「是什么」。

接口用 interface 声明，方法默认是 public abstract，字段默认是 public static final 常量。一个类可以实现多个接口，这弥补了单继承的限制：鸭子既会飞又会游泳，它不需要同时继承两个父类，只需要实现两个接口。

Java 8 之后接口多了默认方法（default）和静态方法，Java 9 又加了私有方法。默认方法的出现是为了解决一个现实问题：接口已经被无数类实现，现在想给它加个新方法，如果加成抽象方法，所有实现类都会编译失败；加成 default 方法，就能提供默认实现，老代码不用改。这是接口的向后兼容演进。

接口的三种方法java
public interface Flyable {
    int MAX_HEIGHT = 10000;        // 常量

    void fly();                    // 抽象方法，实现类必须写

    default void land() {          // 默认方法，可选重写
        System.out.println("缓缓降落");
    }

    static Flyable of(String type) {   // 静态工厂，用接口名调用
        return () -> System.out.println(type + " 起飞");
    }
}

使用接口有一条重要原则：变量声明为接口类型，实现类只出现在 new 的那一刻。例如 List<String> list = new ArrayList<>();，后续代码只依赖 List 这个契约，换成 LinkedList 时只改一行。这就是「面向接口编程」的实际收益。

10.3怎么选：抽象类还是接口

有共同状态和部分实现用抽象类，只约定行为用接口。

对比项抽象类接口
继承/实现数量单继承多实现
成员变量任意类型，可有普通字段只能是 public static final 常量
方法抽象方法 + 普通方法抽象 + default + static + private
构造器有（供子类调用）没有
设计语义is-a，模板复用can-do，能力契约
典型场景有公共状态与固定流程跨类型的能力抽象、解耦

判断方法很直接：问自己「这些类之间有没有血缘关系、有没有共享的状态」。如果有，抽象类更合适；如果只是「都能做某件事」，而彼此毫无关系（比如「可序列化」「可比较」），就用接口。

实际项目里常见两者组合：接口定契约，抽象类给骨架。例如 JDK 的 List 是接口，AbstractList 提供了通用实现，具体类再继承抽象类。这样既有多实现的灵活性，又能复用代码。

10.4内部类：把辅助类藏进主体里

四种形态，差别在于「有没有外部对象」和「能活多久」。

内部类是定义在另一个类内部的类，编译后会生成 Outer$Inner.class 这样的文件。它的价值在于紧密关联：当一个类只服务于另一个类时，把它藏在里面能减少命名污染，还能直接访问外部类的私有成员。

类型定义位置是否持有外部引用典型用途
成员内部类类体中，无 static是，可直接访问外部实例成员需要访问外部对象状态的辅助类
静态内部类类体中，加 static否工具类、Builder、单例持有者
局部内部类方法体内是只在方法内使用的一次性实现
匿名内部类new 的时候是回调、事件监听、临时实现

最需要理解的是「是否持有外部引用」。成员内部类隐含一个 Outer.this，所以必须先有外部对象才能创建（outer.new Inner()），而且只要内部类对象还活着，外部对象就无法被回收——这是内存泄漏的常见来源。静态内部类没有这个引用，可以独立创建，也不影响外部对象回收，所以工具性质的内部类优先声明为 static。

10.5匿名内部类：用完就扔的实现

没有名字、只创建一次，最适合回调和事件处理。

语法是 new 父类或接口() { 重写方法 }。它在定义的同时创建了一个对象，这个类只存在这一次，连名字都不需要。JDK 里大量使用这种写法：线程的 Runnable、比较器的 Comparator、事件监听的 ActionListener。

匿名内部类与 Lambdajava
// 匿名内部类
button.addActionListener(new ActionListener() {
    @Override
    public void actionPerformed(ActionEvent e) {
        System.out.println("被点击了");
    }
});

// 等价的 Lambda（接口只有一个抽象方法时）
button.addActionListener(e -> System.out.println("被点击了"));

Lambda 本质上是匿名内部类的语法糖，但只能用于函数式接口（只有一个抽象方法）。如果接口有多个方法需要实现，还是得写匿名内部类。另外要注意：匿名内部类引用外部局部变量时，该变量必须是 final 或 effectively final——因为它在编译后会被复制到内部类对象里，如果原变量还能改，两份数据就不一致了。

10.6枚举：类型安全的常量集合

用 int 表示状态是万恶之源，枚举把它变成类型。

用 int PENDING = 0 表示订单状态时，编译器无法阻止你传入 99；用枚举后，能传的值被严格限定在声明的那几个，编译期就能检查出来。这就是类型安全。

枚举的每个常量都是这个类的唯一实例，由 JVM 保证。所以它天生适合做单例，也天生适合做「有限状态」。枚举还可以带字段和构造器，用来给每个常量附加描述、编码等信息。

带属性的枚举java
public enum OrderStatus {
    PENDING("待支付", 0),
    PAID("已支付", 1),
    CANCELLED("已取消", -1);

    private final String desc;
    private final int code;

    OrderStatus(String desc, int code) {   // 构造器默认 private
        this.desc = desc; this.code = code;
    }
    public String getDesc() { return desc; }
}

常用方法有三个：values() 返回所有常量的数组，valueOf(String) 按名字转成枚举（名字不存在会抛异常），name() 返回声明时的名字。ordinal() 返回声明顺序，但不要用它做持久化——一旦调整顺序，历史数据就全错了，应该用自己定义的 code 字段。

10.7单例模式：只允许一个实例

配置中心、连接池、日志器——这些对象多一个就会出问题。

单例的实现有三个要素：私有构造器（禁止外部 new）、私有静态实例（自己持有唯一对象）、公共静态获取方法（对外提供入口）。前两个是硬约束，第三个是访问方式。

常见写法有三种。饿汉式在类加载时就创建，简单、天然线程安全，但如果对象很大且从未使用就浪费了。静态内部类利用「类只在首次访问时加载」的特性，实现了延迟加载 + 线程安全，代码最优雅。枚举单例由 JVM 保证唯一，还能防反射、防序列化破坏，是《Effective Java》推荐的做法。

静态内部类单例java
public class Config {
    private Config() { }

    private static class Holder {
        private static final Config INSTANCE = new Config();
    }

    public static Config getInstance() { return Holder.INSTANCE; }
}
懒汉式为什么需要 volatile

经典的「双重检查锁」写法里，instance = new Singleton() 不是原子操作（分配内存、初始化、赋值可能重排）。若不加 volatile，另一个线程可能拿到「已分配但未初始化完成」的半成品对象。日常开发直接用静态内部类或枚举，能少踩这个坑。

小结这一章真正要记住的

Key takeaways

  1. 抽象类不能实例化，但可以有构造器和普通方法。 它把确定的逻辑写好，把不确定的留给子类。
  2. 模板方法：父类定流程，子类填步骤。 这是框架最常见的扩展方式。
  3. 接口是能力契约，支持多实现。 default 方法用于接口的向后兼容演进。
  4. 选型看语义：is-a 且有共享状态用抽象类，can-do 用接口。 实战常见「接口 + 抽象骨架」组合。
  5. 成员内部类持有外部引用，静态内部类不持有。 工具类内部类优先 static，避免内存泄漏。
  6. 匿名内部类是一次性实现，函数式接口可用 Lambda 简化。 Lambda 捕获的变量必须 effectively final。
  7. 枚举是类型安全的常量，天生单例。 持久化用自定义 code，别用 ordinal。
  8. 单例优先用静态内部类或枚举。 懒汉式必须处理并发与指令重排。

自测检查一下你真的懂了吗

抽象类能不能没有抽象方法？能不能被 final 修饰？
可以没有抽象方法（此时仅用于阻止实例化、提供公共实现），但不能加 final，因为 final 禁止继承，与抽象类的存在意义矛盾。
接口中的字段默认是什么修饰符？可以修改吗？
默认 public static final，即常量，必须在声明时赋值且不能修改。
一个类既想继承父类又想实现接口，语法顺序是什么？
class A extends B implements C, D { }。extends 必须在前，implements 在后，多个接口用逗号分隔。
成员内部类和静态内部类的核心区别是什么？为什么工具类内部类建议 static？
成员内部类持有外部类实例的隐式引用（Outer.this），可直接访问外部实例成员，创建时必须先有外部对象，且会阻止外部对象被回收；静态内部类没有这个引用，可独立创建，也不影响外部对象回收。
为什么说枚举是实现单例的最佳方式？
枚举实例由 JVM 保证唯一、构造器天然私有；反射无法创建枚举实例，序列化也只会返回同一个对象，天然免疫这两种破坏单例的方式。
