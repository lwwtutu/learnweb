程序流程控制： 让代码学会选择和重复

顺序执行只能写直线逻辑，现实问题却充满分支和重复。这一章的核心不是记忆语法，而是建立三个判断：什么时候用 if、什么时候用 switch、什么时候用哪种循环。

约 55 分钟 7 个知识点 3 组结构对比 前置：第 03 章

学完这一章，你应该能够

  • 写出结构清晰的多分支判断
  • 判断该用 if 还是 switch
  • 知道四种循环各自的最佳场景
  • 正确使用 break 与 continue
  • 用嵌套循环处理表格型问题
  • 按公式生成指定区间的随机数

任何程序，无论多复杂，最终都由三种结构拼成：顺序（从上到下）、分支（选一条路走）、循环（重复走一段路）。这一章把后两种彻底讲清楚。

4.1if 分支：条件必须是真或假

Java 不接受「非 0 即真」，这既是限制也是保护。

在 C 语言里 if (1) 是合法的，Java 不行：if 括号里必须是 boolean 类型。这个设计消灭了一整类 bug——把 == 误写成 = 时，C 会静默地永远为真，Java 直接编译报错。

多分支 if ... else if ... else 的执行特点是从上往下匹配，命中即结束。这意味着条件的顺序至关重要：如果先判断 score >= 60，那么后面的 >= 90 永远不会进入。写多分支时，要么从严格到宽松，要么从宽松到严格，不能混乱。

多分支的顺序java
if (score >= 90)      System.out.println("A");
else if (score >= 80) System.out.println("B");
else if (score >= 60) System.out.println("C");
else                  System.out.println("D");

还有两个高频错误要避开。一是在 if 条件后多写分号：if (x > 0); 让 if 的语句体变成空语句，后面的代码会无条件执行。二是大括号省略后产生的「悬空 else」：else 永远就近匹配最近的 if，缩进具有欺骗性。规范做法是哪怕只有一行，也写大括号。

4.2switch：等值匹配的专用结构

当判断的是「一个变量等于哪几个固定值」时，switch 比 if 链更清晰。

switch 的适用条件很明确：被判断的表达式是 byte、short、int、char、String 或枚举，且比较的是相等。它不支持范围判断（如 > 60），也不支持 long、float、double、boolean。所以「成绩分段」用 if，「按月份取天数」用 switch。

switch 最具争议的特性是穿透：如果 case 末尾没有 break，会继续执行下一个 case 的代码。这多数时候是 bug，但在「多个值共享同一段逻辑」或「累加」时反而是刻意利用的写法。

合并分支与穿透累加java
switch (month) {
    case 3: case 4: case 5:              // 合并：春季
        System.out.println("春季");
        break;
    case 6: case 7: case 8:
        System.out.println("夏季");
        break;
    default:
        System.out.println("其他");
}

Java 14 之后提供了箭头语法 case 3, 4, 5 -> "春季";，它天然不穿透，还能直接作为表达式返回值。新代码里优先用箭头写法，既短又不会忘记 break。

default 的位置

default 不一定要写在最后，它的意思是「所有 case 都不匹配时执行」。但为了可读性，约定俗成放在最后。另外别忘了：如果所有分支都覆盖了，default 可以省略，但写上更稳妥。

4.3for 循环：次数已知时的首选

三段式把「起点、终点、步长」写在一行，读起来就是一个完整的区间。

for (初始化; 条件; 步进) 的执行顺序是：初始化只执行一次 → 判断条件 → 执行循环体 → 步进 → 再判断。这个顺序要记牢，因为它解释了「为什么循环体里能看到 i 的当前值」以及「为什么条件不满足时循环体一次都不执行」。

for 的三种常见形态java
for (int i = 0; i < 5; i++) { }        // 标准递增
for (int i = 10; i > 0; i -= 2) { }    // 倒序 + 步长
for (int i = 1, j = 10; i < j; i++, j--) { }  // 双变量

循环变量 i 的作用域只在 for 内部，出了循环就不存在。这看似限制，实际是好设计：它避免了「循环结束后 i 的值是几」这类依赖实现细节的代码。如果确实需要在循环外使用下标，就把变量声明提到循环外。

4.4while 与 do-while：次数未知时用它

区别只有一个：先判断还是先执行。

当循环次数无法预先确定，取决于某个条件何时满足时，用 while 更自然。典型例子是「不断读取输入直到用户输入 exit」「一直折纸直到厚度超过珠峰」——你事先不知道要循环多少次。

do-while 的特点是至少执行一次，因为判断在末尾。它最适合菜单这类场景：先显示菜单、接收选择，再判断是否继续，逻辑顺序和人的操作顺序一致。

循环执行顺序最少执行最佳场景
for初始化 → 判断 → 循环体 → 步进0 次次数已知、需要下标
while判断 → 循环体0 次次数未知、条件驱动
do-while循环体 → 判断1 次菜单、至少执行一次
死循环不是 bug，忘了退出才是

while 循环里如果忘记修改条件变量，就会永远执行下去。写循环时先问自己两个问题：条件最终会变假吗？ 如果不会，那这个循环是否由内部 break 结束？

4.5break 与 continue：跳出与跳过

一个是终止整个循环，一个是跳过一次迭代。

这两个关键字常被混用。break 立即结束当前循环，执行循环之后的代码；continue 只结束本次迭代，直接进入下一次判断。在「查找」场景里用 break（找到就停，不必再找），在「过滤」场景里用 continue（跳过不符合条件的元素）。

嵌套循环中，break 默认只跳出最内层。想一次跳出多层，可以给外层循环加标签：outer:，然后 break outer;。这个语法不常用，但在二维数组查找、矩阵遍历中很有价值。

标签跳出多层java
outer:
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (i == 1 && j == 1) break outer;
    }
}

标签语法容易被滥用。如果发现自己需要跳出三层以上，通常说明这段逻辑应该抽成一个方法，用 return 直接结束更清晰。

4.6嵌套循环：外层管行，内层管列

所有图形打印、表格遍历、排列组合，都是同一个套路。

嵌套循环的思考方式不是「让代码跑起来」，而是先想清楚图形的规律，再翻译成两个变量。打印直角三角形：外层 i 控制第几行，内层 j 控制这一行打印几个——因为第 i 行要打印 i 个，所以内层条件是 j <= i。打印倒三角则要多一层：先打空格，再打星号。

九九乘法表java
for (int i = 1; i <= 9; i++) {
    for (int j = 1; j <= i; j++) {
        System.out.print(j + "*" + i + "=" + (i * j) + "\t");
    }
    System.out.println();     // 每行结束换行
}

时间复杂度也在这里第一次出现：两层循环各执行 n 次，总次数是 n²。这解释了为什么冒泡排序、选择排序是 O(n²)——它们本质上就是嵌套循环。后面学算法时，「能不能把两层循环降成一层」是最常见的优化方向。

4.7Random：让程序有不确定性

记住一个公式，就能生成任意区间的整数。

Random.nextInt(n) 返回 [0, n) 的整数——注意是左闭右开，取不到 n。想得到任意区间 [min, max]，公式是 nextInt(max - min + 1) + min。区间长度决定参数，起点决定偏移量。

区间随机数java
Random r = new Random();
r.nextInt(100);            // [0, 100)
r.nextInt(100) + 1;        // [1, 100]
r.nextInt(11) + 10;        // [10, 20]
r.nextInt(6) + 1;          // 掷骰子

另一个常用工具是 Math.random()，它返回 [0.0, 1.0) 的 double，需要自己乘区间。Random 更直观，还能指定种子复现随机序列——这在测试和游戏回放中很有用。

随机不等于均匀可信

Random 是伪随机，用确定性算法生成看起来随机的序列。用在抽奖、验证码上没问题，但涉及安全场景（如令牌生成）应使用 SecureRandom。

小结这一章真正要记住的

Key takeaways

  1. 条件必须是 boolean。 把 == 写成 = 会编译报错，这是 Java 的保护。
  2. 多分支从上往下匹配，命中即结束。 条件顺序错了，后面的分支永远进不去。
  3. switch 只做等值匹配。 忘记 break 会穿透；新代码优先用箭头语法。
  4. 次数已知用 for，次数未知用 while，至少一次用 do-while。
  5. break 结束整个循环，continue 只跳过本次。 多层跳出用标签，但更推荐抽方法。
  6. 嵌套循环先找规律再写代码。 外层控制行，内层控制列。
  7. 区间随机数公式：nextInt(max-min+1) + min。

自测检查一下你真的懂了吗

switch 的 case 后面忘了写 break 会发生什么？什么情况下这是故意的？
发生穿透：从匹配到的 case 开始，一直执行到 break 或 switch 结束。多个值共享同一段逻辑（如 3、4、5 月都是春季）或需要累加时，会刻意利用穿透，但要加注释说明。
while 与 do-while 的核心区别是什么？举一个只能用 do-while 更自然的场景。
while 先判断后执行，可能一次都不执行；do-while 先执行后判断，至少执行一次。控制台菜单（先显示菜单再判断用户输入）用 do-while 更自然。
下面代码输出什么？for (int i = 0; i < 3; i++) { if (i == 1) continue; System.out.print(i); }
输出 02。i 为 1 时 continue 直接进入下一轮，跳过打印。
要生成 [5, 15] 的随机整数，代码怎么写？为什么参数是 11 不是 15？
new Random().nextInt(11) + 5。区间长度 = 15 - 5 + 1 = 11，nextInt 取不到上界，所以要加 1 才能包含 15。
为什么说嵌套循环的性能问题本质是 n²？
外层执行 n 次，每次内层也执行约 n 次，总操作次数约 n×n。数据量翻倍，耗时会变成四倍，这就是 O(n²) 算法在大数据量下不可用的原因。
