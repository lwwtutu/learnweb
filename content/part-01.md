### 在控制台里验证一切

学习 JS 最有效的办法，是把每段代码亲手敲进浏览器控制台，看它真正返回什么。只读结论容易记成死知识，敲一遍才算确认过，所以这个动作要贯穿整个入门过程。

```js
1 + 2                 // => 3
"hello" + " world"   // => "hello world"
```

上面两行分别演示数字相加与字符串拼接，结果都直接回显在下一行。先照着敲，比先背规则更容易建立直觉。

### 打开控制台

按 `F12`，或在页面上右键选择「检查」，再切到 Console 面板。它是一个输入即执行的环境：不用新建文件，也不用刷新页面，敲完按回车就能看到回显。

```js
console.log("hello")   // => hello
```

`console.log()` 把内容打印到控制台，是后面最常用的输出方式。控制台另有 `console.error()` 显示红色、`console.warn()` 显示黄色，用来区分信息级别。

> 💡 控制台保留历史输入，按方向键上、下能找回之前敲过的表达式，便于反复对比。

### 输出结果的约定

这里说的「输出结果」，一律指控制台里看到的内容，不是页面文字，也不是弹窗。代码块统一用 `// =>` 在语句后面标出该行的返回值，读的时候可以直接对照，不必另开环境去猜。

| 写法 | 含义 |
|---|---|
| `// =>` | 该行代码执行后的结果 |
| `> ⚠️` | 真正必要的易错提醒 |
| `> 🧠` | 值得记住的结论 |

因为全书都按这个约定写，先认清这三个记号，后面读示例才不会混淆「代码」和「结果」。

### 为什么强调即时反馈

写错一个括号会立刻看到红色报错，改完再回车就能验证，试错成本几乎为零。这样后面遇到变量、类型转换、运算符这些容易混淆的概念时，就能用最小代价确认理解是否正确。

> 💡 把「敲一遍、看一眼」固定成习惯，比多读几遍结论更有用。

### 来历与名字

1995 年，网景公司的 Brendan Eich 用大约十天设计出这门语言，最初叫 LiveScript。为了借当时 Java 的声势，才改名为 JavaScript；名字里带 Java，但两者在语法和设计上毫无关系。

后来语言被标准化，标准名称是 ECMAScript，简称 ES。平时说的「ES6」，指的就是第 6 版语法规范，因为版本是按标准文档来编号的。

> 🧠 一句话记牢：JavaScript 不等于 Java，官方标准名是 ECMAScript。

### 三个组成部分

一套完整的 JS 分成三块，划分依据是「操作的对象是什么」，理解这一点才能明白后面的学习顺序。

```text
JavaScript
├── ECMAScript   语法规则本身
├── BOM          操作浏览器窗口
└── DOM          操作页面元素
```

| 组成 | 作用 | 典型内容 |
|---|---|---|
| ECMAScript | 语言本身的语法规则 | 变量、数据类型、运算符、函数、对象 |
| BOM | 操作浏览器 | 弹窗、地址栏、历史记录、本地存储 |
| DOM | 操作页面元素 | 取元素、改文字、改样式、绑定事件 |

这个划分决定了学习顺序：先把 ECMAScript 这套语法学扎实，再分别展开 BOM 与 DOM。两部分用的是同一套语法，差别只在操作目标不同，所以切换时不需要重学语言本身。

### 一句话定位

把三块合起来看，JS 的本质是用固定的语法去操作浏览器和页面元素，从而实现各种交互效果。语法是工具，交互是目的。

因为 BOM 和 DOM 只是换了一批可操作的对象，把语法练熟之后，后面学新 API 主要记的是「能操作什么」，而不是「代码该怎么写」。

### 三种输出方式

```js
alert("hello world")           // 浏览器弹窗
console.log("hello world")     // 控制台可见
document.write("hello world")  // 写入页面正文
```

三者的调用形式一致，都是函数名加括号，把要展示的内容作为参数传进去。区别在于内容出现在哪里，这决定了各自适用的场景。

| 方法 | 出现位置 | 特点 | 适用场景 |
|---|---|---|---|
| `alert()` | 浏览器弹窗 | 阻塞页面，不点确定不往下走 | 教学演示 |
| `console.log()` | 控制台 | 不打扰用户，可连看多条 | 调试首选 |
| `document.write()` | 页面正文 | 直接写入文档 | 基本不用 |

日常主力只有 `console.log()`。因为它不会打断用户，还能一次查看多条记录；控制台另有 `console.error()` 显示红色、`console.warn()` 显示黄色，用来区分信息级别。

### document.write 的陷阱

如果 `document.write()` 在页面加载完成之后才执行，例如放在某个点击处理里，它会把整个文档清空，只留下这一次写入的内容。

原因是文档流已经关闭，再写入相当于重新打开一份新文档，旧内容会被整个覆盖。因此实际项目里不要使用它，调试请回到 `console.log()`。

### 顺带认识字符串

`alert(...)` 括号里的内容叫参数，意思是「要展示给谁看」。被引号包裹的文本叫字符串，这部分在第 7 章展开。

```js
alert("hello world")     // 参数是字符串 "hello world"
```

有一个高频错误要提前避开：括号与引号必须写成英文半角。因为中文引号不被词法识别，用中文引号会直接报错，输入法状态是新手最常见的报错来源。

> ⚠️ JS 里所有标点都用英文半角。

### 补充笔记：console 家族

`console` 除了最常用的 `log`，还有两个按级别区分信息的方法。三者用法一样，只是显示颜色不同，便于在大量输出里快速分辨。

```js
console.log("普通信息")
console.error("错误信息")
console.warn("警告信息")
```

三段代码分别打印普通、红色、黄色信息；入门阶段绝大多数输出仍用 `log`，另两个留到需要区分级别时再用。

title: JS 写在哪里
lessons: 004
summary: 行内、内嵌、外链三种写法中外链最利维护，脚本位置决定执行时机
points: 行内式靠点击触发，不推荐正式使用 || 内嵌与外链在解析到 script 标签时执行 || 操作元素的脚本必须放在目标元素之后 || 外链式让 HTML 与 JS 彻底分离，最易维护 || 带 src 的 script 标签内代码会被忽略
===BODY===
### 行内式：写在标签属性里

行内式把 JS 直接塞进 HTML 标签的属性，必须靠点击等用户动作触发，页面打开时不会执行。

```html
<button onclick="alert('hello')">点我</button>
<a href="javascript:;">阻止跳转</a>
```

`javascript:` 是一种伪协议，告诉浏览器后面不是网址而是代码；实际常写 `javascript:;` 来阻止链接跳转。这种写法让 HTML 与 JS 混在一起，无法复用，后期维护要翻遍页面才能找到代码，因此正式项目不用。

### 内嵌式：写在 script 标签中

内嵌式把代码包进 `<script>` 标签，页面解析到它就执行，不需要用户操作。位置决定时机，这一点最容易被忽略。

```html
<!-- 脚本写在元素之前 -->
<script>
    console.log(document.querySelector("div"))  // => null
</script>
<div>hello</div>
```

因为浏览器从上往下解析 HTML，脚本执行时下方的 `<div>` 还没生成，查询结果是 `null`。把脚本移到元素之后，就能正常拿到该元素。

> 🧠 要操作页面元素的脚本，通常放在 body 末尾、目标元素之后。

把顺序反过来，脚本放在 `<div>` 之后，浏览器解析到脚本时元素已经存在，查询结果就不再是空值。

```html
<body>
    <div>hello</div>
    <script>
        console.log(document.querySelector("div"))  // => <div>hello</div>
    </script>
</body>
```

这正好验证了位置决定时机：改的只是标签顺序，查询就从 `null` 变成拿到元素。

### 外链式：独立成文件

外链式把 JS 单独放进文件，用 `src` 引入，页面解析到标签时执行。它让 HTML 与 JS 彻底分离，便于单独缓存和复用，最好维护。

```html
<script src="js/hello.js"></script>
```

下面三个坑都与 `src` 标签的写法有关：

- 带 `src` 的标签，其内部写的代码会被忽略。
- 标签不能自闭合，否则后面的 HTML 全部失效。
- `src` 路径写错不会报错，只是什么都不发生。

因为路径错误没有任何提示，排查时应当先确认文件位置，再去看代码逻辑。

### 三种写法对比

| 写法 | 执行时机 | 推荐度 | 用途 |
|---|---|---|---|
| 行内式 | 用户触发（点击等） | 低 | 临时测试 |
| 内嵌式 | 解析到该标签时 | 中 | 单页少量代码 |
| 外链式 | 解析到该标签时 | 高 | 正式项目一律使用 |

三者的差别集中在两点：谁触发执行、代码放在哪里。因为内嵌与外链都在解析到标签时运行，选外链主要是为了让结构与行为分离，而不是为了改变执行时机。

### 两种注释

注释会被引擎完全忽略，不参与执行，只给人看。单行用双斜杠，多行用斜杠加星号包裹。

```js
// 单行注释：作用于这一行，快捷键 Ctrl + /

/*
   多行注释：包裹一整段
   快捷键 Alt + Shift + A
*/
```

因为引擎会跳过整段注释文字，所以写多少说明都不会影响运行结果，可以放心交代背景与约束。

### 注释该写什么

```js
var n = 18      // 把 18 赋值给 n（复述代码）
var age = 18    // 满 18 才允许注册（点明原因）
```

判断标准很直接：读完注释应该明白这段代码「为什么存在」，而不是把语句又翻译一遍。第一行只是复述，没有信息量；第二行交代了业务约束，才值得留下，因为改代码的人需要知道这条限制。

### 空格与换行

引擎按「词」解析，只要 `console`、`log`、字符串这些词完整，中间插多少空格和换行都不影响运行，甚至把一条语句拆成多行也能正常输出。

```js
console.
log(
"hello world"
)                       // => hello world
```

但不要据此随意乱写，因为空格放在某些位置会改变表达式含义：两个连着的加号会被拆成正号与加号，结果可能完全不同。

```js
1 + 2        // => 3
1 + + 2      // => 3   分别是正号与加号
1 + + "2"    // => 3   字符串先被转成数字
```

风格上保持一行一句、读得顺口即可，不必追求把语句写得零散。

### 代码规范

1. 一行只写一句代码。
2. 运算符两侧各留一个空格，如 `a = b + c`。
3. 代码块统一缩进，4 个或 2 个空格，一个项目内保持一致。
4. 语句结尾补分号 `;`；引擎虽能自动插入，显式写出更稳妥。
5. 变量名要表意，避免 `a`、`b`、`c` 这类无意义命名。

这些约定不改变运行结果，目的是让代码便于协作阅读。编辑器里 `Shift + Alt + F` 可一键格式化，养成随手整理的习惯。

下面这组对照把规范落到代码上：前两行命名表意、间距统一，后两行虽然也能跑，读起来却费劲。

```js
var num = 10
var totalPrice = 100

var a=10
var   totalprice    =    100
```

两者运行结果没有差别，区别只在可读性；项目里应始终按前一种写。

points: 变量是给数据起的名字，对应一块内存空间 || 赋值号表示把值装进变量，不是数学上的等于 || 同名变量再次赋值会覆盖原值且不可恢复 || 变量名严格区分大小写 || 声明但未赋值的变量值为 undefined

### 变量是什么

变量可以理解为贴了标签的盒子：盒子是内存空间，标签是变量名，里面装的是数据。它给一块数据起名字，之后通过名字反复取用，避免每次都重写值本身。

```js
var age = 18
console.log(age)    // => 18
```

这一行里，`var` 是声明变量的关键字，`age` 是变量名，`=` 表示把右侧装进左侧，不是数学上的相等，`18` 是值。

### 声明与赋值的几种写法

可以先声明再赋值，也可以声明时直接赋值，后者更常用。变量一旦有值就能参与运算，例如赋给另一个变量继续相加。

```js
var x
x = 100             // 先声明，后赋值

var z = x + 2000
console.log(z)      // => 2100
```

多个变量可用一条 `var` 一次声明，用逗号分隔。因为逗号是分隔符，漏写会让两个变量连在一起，直接造成语法错误。

```js
var i, j, k         // 一次声明多个，值都是 undefined
var a = 1, b = 2, c = 3
```

### 三条铁律

| 规则 | 说明 |
|---|---|
| 单值覆盖 | 同名变量再次赋值会覆盖旧值，原值不再保留 |
| 区分大小写 | `Name` 与 `name` 是两个不同变量 |
| 未赋值即 undefined | 声明后没给值，读取结果是 `undefined` |

覆盖意味着旧值找不回来，所以给同一变量重新赋值前，要确认不再需要原来的数据。大小写敏感则是因为引擎把变量名当作完全不同的字符串来查找。

表格里的三条规则，用代码跑一遍会更直观。

```js
var n = 10
n = 20
console.log(n) // => 20

var Name = "张三"
var name = "李四"
console.log(Name, name) // => 张三 李四

var q
console.log(q) // => undefined
```

注意 `Name` 与 `name` 同时存在且互不影响，说明引擎把它们当成两个完全不同的名字。

### 交换两个变量

```js
var m = 5
var n = 6
var temp

temp = m
m = n
n = temp
console.log(m, n)   // => 6 5
```

交换必须借一个临时变量当中转。因为直接互相赋值会先把其中一个值冲掉，另一个值再也找不回来，相当于三个杯子倒水得先留一个空杯。

> ⚠️ var 可重复声明、不声明直接赋值会变成全局变量、也没有块级作用域；这三点都是它自身的局限，写代码时要有意识地规避。

### 规则与规范的区别

| 概念 | 强制性 | 违反后果 |
|---|---|---|
| 规则 | 语言层面强制 | 直接报错，代码无法运行 |
| 规范 | 行业约定，建议遵守 | 不报错，但可读性差、难协作 |

规则决定能不能跑，规范决定好不好读。因为两者的约束层面不同，判断一个名字合不合格时，要先看是否触犯规则，再看它是否表意。

### 五条命名规则

命名规则由语言强制，违反任意一条都会直接报错。

1. 组成字符只能是字母、数字、下划线 `_` 和 `$`。
2. 不能以数字开头。
3. 严格区分大小写，`A1` 与 `a1` 是两个变量。
4. 不能占用关键字或保留字，例如 `var`、`if`、`for`、`function`、`return`、`class`、`typeof`、`true`、`false`、`null`。
5. 名字中间不能有空格。

```js
var a1 = 1
var a_1 = 2
var $box = 3
var userName = "张三"
```

像 `1a`（数字开头）、`class`（关键字）、`good number`（含空格）这类写法都会报错。名字里虽然允许 `$`，但它多被类库当作特殊前缀使用，业务变量里不必刻意跟着用，因为那会让命名显得杂乱。

### 三条命名规范

规范不强制，目的是让名字本身能传递信息，便于协作。

1. 语义化：名字要能看出装的是什么，避免 `a`、`b`、`c`。
2. 多单词用驼峰：`goodNumber` 首选；`good_number` 也能用，但一个项目内要统一；`goodnumber` 连写看不出单词边界，不推荐。

### 两大类：按存储方式划分

JS 的数据类型先分成基本与复杂两大类，划分依据是「值放在哪里」。因为两类在内存里的存法不同，后面赋值、比较时的表现差别很大。

| 分类 | 包含类型 | 存储方式 |
|---|---|---|
| 基本数据类型 | Number、String、Boolean、Undefined、Null | 值直接存在变量里 |
| 复杂数据类型 | Object（含 Array、Function） | 变量只存指向另一块内存的地址 |

能整块装进变量的是基本类型；数据另存一处、变量里只记一个地址的，是复杂类型。ES6 之后基本类型还多出一种 Symbol，此处先按五种记忆，因为入门阶段几乎用不到它。

### Number：整数与小数共用一个类型

JS 不区分整数与小数，两者都是 `number`。这样设计让数值运算不必先判断类型，代价是所有数字都按双精度浮点存储，会出现 `0.1 + 0.2` 这类精度误差。

```js
var age = 18
var price = 12.5
console.log(typeof age, typeof price)   // => "number" "number"
console.log(2e3)                        // => 2000
console.log(0.1 + 0.2)                  // => 0.30000000000000004
```

`e` 表示 10 的幂，`2e3` 即 2 × 10³。进制用前缀区分，写错前缀会得到完全不同的值。

| 写法 | 含义 | 值 |
|---|---|---|
| `2e3` | 2 × 10³ | 2000 |
| `0xff` | 十六进制 | 255 |
| `0b11` | 二进制 | 3 |
| `0o77` | 八进制（推荐） | 63 |

> ⚠️ 老式 `077`（0 开头）在严格模式下会报错，一律写 `0o77`。

#### NaN：运算失败的结果

除法、转换失败不会抛错，而是返回 `NaN`。它表示「不是有效数字」，但因为属于数字运算失败后的结果，`typeof` 仍是 `number`。

```js
console.log(10 / "abc")    // => NaN
console.log(typeof NaN)    // => "number"
console.log(NaN === NaN)   // => false
console.log(isNaN(NaN))    // => true
```

`NaN` 是唯一不等于自身的值，所以判断要用 `isNaN()`，不能用 `===`。这一点在做表单校验时尤其要注意，因为用户输入非法内容往往就得到 `NaN`。

### String：引号包裹的一切

被引号包裹的内容都是字符串，单双引号等价。之所以有两种引号，是为了方便在字符串里直接嵌套另一种引号，不必每次都转义。

```js
var s1 = "kerwin"
var s2 = '我说："你好"'      // 外单内双，合法
var s3 = "他说：\"你好\""   // 用 \" 转义出双引号
console.log(s1, s2)         // => kerwin 我说："你好"
```

反斜杠 `\` 让特殊字符变普通：`\n` 换行、`\t` 制表符、`\\` 表示反斜杠本身。因为引号要成对闭合，内外层混用不同引号最省事。

转义的实际效果可以用三段字符串看清：`\"` 输出引号，另外两个插入控制字符。

```js
var s1 = "他说：\"你好\""
var s2 = "第一行\n第二行"
var s3 = "姓名\t年龄"
```

控制台里第二行会分行显示，第三行的姓名与年龄之间留出一段空白，这就是 `\n` 与 `\t` 的作用。

### Boolean：只有两个值

布尔只有 `true` 和 `false`，用来表示开关状态，例如复选框是否勾选。它常作为条件判断的结果，因为 `if` 内部就是把值转成布尔再决定走哪条分支。

```js
var isChecked = false
console.log(isChecked)      // => false
console.log(typeof true)    // => "boolean"
console.log(typeof "true")  // => "string"
```

带引号的 `"true"` 是字符串，与布尔 `true` 完全不同。typeof 的结果可以直接证明这一点，这也是表单取值里最容易混淆的地方。

### Undefined 与 Null：两种「空」

这两种类型都表示「没有值」，但来源完全不同，所以在代码里承担的职责也不一样。下面分别说明，再用一张表对照。

#### Undefined：没给值时的默认值

声明了变量却没赋值，读取结果是 `undefined`。这是 JS 自动给的，意味着「系统还没等到值」，不应该由程序员手动写入。

```js
var which
console.log(which)   // => undefined
which = 100
console.log(which)   // => 100
```

因为它是系统行为，手动写 `var a = undefined` 没有意义；要表达「现在是空的」，应当用 `null`。

#### Null：程序员主动置空

`null` 只有一个值，表示「这里暂时没有对象」。它由程序员主动写入，常见于先声明一个空引用、等有数据了再填进去的场景下。

```js
var whichObject = null           // 先占个位
whichObject = { name: "kerwin" }
console.log(whichObject)         // => { name: "kerwin" }
```

这样写的好处是变量名可以提前确定，后续逻辑不必改；代价是要记得用之前先判断它是否还是 `null`。

#### null 与 undefined 对照表

把前面的差别整理成表，便于对照记忆，尤其注意两者转成数值时结果并不相同。

| 对比项 | undefined | null |
|---|---|---|
| 谁造成的 | JS 自动给出 | 程序员手动写入 |
| 典型场景 | `var a` 没赋值；函数没 return | 想表示「暂时没有」，先占位 |
| 语义 | 忘了给值 | 主动清空 |
| 转数值 | `NaN` | `0` |

> 🧠 一句话区分：`null` 是「我主动清空」，`undefined` 是「我忘了给」。

### 类型会悄悄变化

运算时值的类型并不一定保持不变，最典型的是 `+` 遇到字符串。因为引擎会自动做隐式转换，写表达式时若不留意类型，结果往往出人意料。

```js
var num1 = 10
var num2 = "20"
console.log(num1 + num2)   // => "1020"
```

这里 `+` 转为拼接，得到 `"1020"` 而不是 `30`。页面输入框读出的值永远是字符串，所以这类现象非常普遍，正是下一章数据类型转换要解决的问题。

### 两种写法与本质

```js
var a = 100
console.log(typeof a)     // => "number"
console.log(typeof(a))    // => "number"
```

两种写法等价，`typeof a` 更常见。它不改动原值，只查看类型并返回一个描述类型的字符串，不要理解成「转换」，因为它对数据本身没有任何副作用。

### 各类型的检测结果

| 表达式 | 返回值 |
|---|---|
| `typeof 100` | `"number"` |
| `typeof "abc"` | `"string"` |
| `typeof true` | `"boolean"` |
| `typeof undefined` | `"undefined"` |
| `typeof null` | `"object"` |
| `typeof []` | `"object"` |
| `typeof function(){}` | `"function"` |
| `typeof NaN` | `"number"` |

`typeof null` 返回 `"object"` 是 1995 年留下、因兼容老网站而无法修复的著名缺陷。判断 `null` 应直接写 `b === null`，因为依赖 typeof 反而会把它当成对象。

数组同样返回 `"object"`，说明它分不清数组与普通对象，要精确判断得用 `Array.isArray([])`；函数则返回独有的 `"function"`，这是唯一能直接区分出来的复杂类型。

把几种复杂类型放在一起测，差异一眼就能看出来。

```js
typeof {}             // => "object"
typeof []             // => "object"
typeof function(){}   // => "function"
Array.isArray([])     // => true
```

前两行结果相同，证明 `typeof` 分不清数组和对象；想知道是不是数组，只能靠第四行那个专门的方法。

### 返回值恒为字符串

```js
var a = 100
console.log(typeof typeof a)   // => "string"
```

内层 `typeof a` 先得到 `"number"`，外层再对这个字符串检测，结果必然是 `"string"`。正因为返回值永远是字符串，嵌套多少层都一样，这一点常被用来出考题。

### 优先级与实用场景

`typeof` 是一元运算符，优先级高于 `+`。`typeof a + 100` 会先算成 `"number" + 100` 得到 `"number100"`，只有加括号写成 `typeof (a + 100)` 才返回 `"number"`，拿不准就加括号。

```js
var a = 100
console.log(typeof a + 100)     // => "number100"
console.log(typeof (a + 100))   // => "number"
```

它有三类典型用途：判断输入是否为字符串、判断函数后再调用、判断变量是否声明过。直接写 `if (abc)` 在 `abc` 未声明时会抛错，而 `typeof abc` 对未声明变量也安全，只返回 `"undefined"`。

可见 `typeof` 只回答「属于哪一类」，并不分辨具体值；遇到 `null` 或数组时，还得配合全等比较与 `Array.isArray()` 才能得出准确结论。

### 为什么要转换

从 `input`、`prompt` 取到的值一律是字符串，用户输入的 `18` 实际是 `"18"`。因为直接拿字符串参与比较会按字符编码算，计算前必须先转成数字，否则结果会悄悄出错。

| 方式 | 写法 | 特点 |
|---|---|---|
| 显式（强制） | `Number(x)` / `String(x)` / `Boolean(x)` | 主动转换，推荐 |
| 方法 | `x.toString()` / `parseInt(x)` | 调用对象上的方法 |
| 隐式 | `"100" * 1` / `100 + ""` | 引擎自动完成，易踩坑 |

三类方式里显式转换最可控，因为意图写在代码里，别人一眼能看出这里要换类型；隐式转换虽然短，却把规则藏在了运算符背后。

### 转成数值

#### Number()：整段必须合法

`Number()` 最严格，要求整段内容都是合法数字，多一个字符就得到 `NaN`。空字符串与全空格转 `0`，`null` 转 `0`，`undefined` 转 `NaN`，`true` 与 `false` 转 `1` 与 `0`。

```js
Number("12.5")      // => 12.5
Number("123abc")    // => NaN
Number("")          // => 0
Number(null)        // => 0
Number(undefined)   // => NaN
Number(true)        // => 1
```

之所以把空串和 `null` 都转成 `0`，是历史规则使然；正因为这样，`Number(undefined)` 得到 `NaN` 才显得反直觉，需要单独记。

#### parseInt() 与 parseFloat()：从左侧逐字符读

这两个函数宽松得多，从左侧逐字符读取，遇到非数字就停，因此 `"100px"` 能取出 `100`。`parseInt()` 丢弃小数，直接截断而不是四舍五入；`parseFloat()` 保留第一个小数点。

```js
parseInt("100px")     // => 100
parseInt("12.9")      // => 12
parseInt("abc123")    // => NaN
parseFloat("1.25rem") // => 1.25
parseFloat("1.2.3")   // => 1.2
```

因为截取的是「开头那段」，做动画时常用 `parseInt("10px")` 去掉单位；开头就不是数字则直接失败，返回 `NaN`。

再看几个输入，能看清这两个函数处理空格与前缀时的细节。

```js
parseInt("  -42  ")      // => -42
parseInt("0xff")         // => 255
parseFloat("3.1415abc")  // => 3.1415
```

首行说明它会忽略前后空格，次行说明 `0x` 前缀被当作十六进制，末行则在字母处停下，只保留开头的小数。

把三个函数的差别整理成表，便于按需求挑选，下面再用同一个字符串验证一次。

| 方法 | 要求 | 小数 | 失败时 |
|---|---|---|---|
| `Number()` | 整段合法 | 保留 | `NaN` |
| `parseInt()` | 开头是数字即可 | 截断 | `NaN` |
| `parseFloat()` | 开头是数字即可 | 保留 | `NaN` |

```js
var s = "100px"
Number(s)      // => NaN
parseInt(s)    // => 100
parseFloat(s)  // => 100
```

同一个字符串三个函数结果不同，原因就在「整段合法」与「读开头」这两种判定方式。

#### 隐式转换：用算术运算逼出数字

`-`、`*`、`/`、`%` 会把操作数自动转成数字，唯独 `+` 特殊，遇到字符串就变成拼接。因为这是引擎自动做的，写的时候容易忽略类型，表单计算更推荐显式 `Number()`。

```js
"100" * 1       // => 100
"100" - 0       // => 100
"100" + 0       // => "1000"
"abc" * 1       // => NaN
```

> ⚠️ `"100" + 1` 得到 `"1001"`，不是 `101`，加号优先按拼接处理。

### 转成字符串

#### String()：所有类型都能转

`String()` 适用于所有类型，包括 `null` 和 `undefined`，是最稳妥的写法。因为它不依赖值身上有没有方法，任何输入都能得到字符串。

```js
String(100)        // => "100"
String(true)       // => "true"
String(null)       // => "null"
String(undefined)  // => "undefined"
```

#### toString()：两个类型不能用

`toString()` 效果与 `String()` 相同，但 `null` 和 `undefined` 身上没有任何方法，调用会抛 `TypeError`。数字字面量后直接跟点会被当成小数点，需写成 `(100).toString()`。

```js
(100).toString()   // => "100"
true.toString()    // => "true"
100..toString()    // => "100"   两个点也行
```

#### 拼接空串：最省事的写法

最偷懒也最常用的做法是 `+ ""`。因为 `+` 遇到字符串就拼接，任何值加上空串都会变成字符串，控制台里带引号显示的就是它。

```js
100 + ""        // => "100"
true + ""       // => "true"
null + ""       // => "null"
```

### 转成布尔

`Boolean()` 转出 `false` 的只有六类值：`false` 本身、`""`、`0`、`NaN`、`null`、`undefined`（严格说 `-0`、`0n` 也算假值）。除此之外一律 `true`。

| 原值 | 转布尔 | 说明 |
|---|---|---|
| `""` | `false` | 空字符串 |
| `0` / `NaN` | `false` | 零与无效数字 |
| `null` / `undefined` | `false` | 两种空 |
| `"0"` | `true` | 非空字符串，最高频误判 |
| `"false"` / `" "` | `true` | 带内容就是真值 |
| `[]` / `{}` | `true` | 空数组、空对象也是真值 |

```js
Boolean("")      // => false
Boolean("0")     // => true
Boolean([])      // => true
```

后面所有 `if` 判断与逻辑运算，底层都按这套真假规则执行，因为引擎会先把条件转成布尔再决定分支。字符串 `"0"` 与空数组最容易判断错，要特别留意。

### 五类运算符一览

本章按数学、赋值、比较、逻辑、自增自减五类展开。先看全貌，因为不同类别的结果类型并不一样，混用时最容易在这里出错。

| 类别 | 符号 | 结果类型 | 关键规则 |
|---|---|---|---|
| 数学 | `+ - * / %` | 数字 | `+` 遇字符串转拼接，其余运算自动转数字 |
| 赋值 | `= += -= *= /= %=` | 取决于右侧 | `=` 是装值不是判等 |
| 比较 | `> < >= <= == === != !==` | 布尔 | 一律用全等，字符串按字符编码比较 |
| 逻辑 | `&&` / `\|\|` / `!` | 布尔或原值 | 返回原始值，具备短路特性 |
| 自增自减 | `++ --` | 数字 | 只能作用于变量，前置先变后用、后置先用后变 |

其中比较运算符的结果恒为布尔，逻辑运算符却可能返回原始值；先把这条差别记住，后面几节就不容易混淆。

### 数学运算符

`+` 有双重身份：两边都是数字时做加法，任意一边是字符串就变成拼接。因为拼接优先于加法，`"1" + 2 + 3` 会从第一处开始一路拼成 `"123"`。

```js
10 + 20        // => 30
"10" + 20      // => "1020"
1 + 2 + "3"    // => "33"
```

`-`、`*`、`/`、`%` 始终尝试把两边转成数字。`%` 取余常用于整除判断，`/` 不会自动取整，`1 / 0` 得 `Infinity`，`0 / 0` 得 `NaN`。

```js
10 % 3         // => 1
10 / 4         // => 2.5
"10" - 5       // => 5
```

用 `parseInt(a / 60)` 配合 `a % 60` 可把总分钟数拆成小时与剩余分钟，因为前者砍掉小数、后者取余，正好互补。

把总分钟数拆成时分，正好把这两个运算放在同一段代码里。

```js
var a = 1000                 // 总分钟数
var b = parseInt(a / 60)     // 小时：1000 / 60 = 16.666 → 16
var c = a % 60               // 分钟：1000 ÷ 60 余 40
console.log(b + ":" + c)     // => "16:40"
```

`parseInt` 砍掉小时的小数，`%` 留下除不尽的分钟；中间的冒号是字符串，整个表达式最终拼成 `16:40`。

优先级上括号最高、赋值最低，拿不准就加括号，避免依赖记忆去判断结合顺序。

### 赋值运算符

`=` 是把右侧值装进左侧变量，判等要用 `==` 或 `===`。因为二者长得很像，新手最常把「赋值」写成「判断」，导致条件永远为真。

```js
var a = 1
a = 2
console.log(a)   // => 2
```

`+=`、`-=` 等复合形式等价于先运算再回写，好处是少写一遍变量名。但 `a += "5"` 受拼接规则影响，得到 `"55"`。

链式赋值从右往左执行，别写成 `var a = b = 100`，否则 `b` 会变成隐式全局变量。

```js
var number = 5
number += 1      // => 6
number *= 3      // => 18
```

### 比较运算符

比较结果一定是布尔值。`==` 只比值、会偷偷转换类型，`===` 同时比值和类型，开发时一律用后者，因为隐式转换会产生一批反直觉结果。

```js
1 == "1"           // => true
1 === "1"          // => false
null == undefined  // => true
NaN === NaN        // => false
```

| 符号 | 名称 | 比较内容 | 建议 |
|---|---|---|---|
| `==` | 相等 | 只比值，会转换类型 | 少用 |
| `===` | 全等 | 比值 + 比类型 | 一律用它 |
| `!=` | 不等 | 只比值 | 少用 |
| `!==` | 不全等 | 比值 + 类型 | 用它 |

`==` 下 `"" == 0` 为真、`null == 0` 却为假，这类差别正是要避开它的原因。字符串按字符编码逐位比较，所以 `"10" < "9"` 成立，输入框取到的值必须先 `Number()` 再比较。

### 逻辑运算符

`&&` 两真才真、`||` 一真即真、`!` 取反，`!!x` 可把任意值转成布尔。但它们返回的是原始值，因为引擎先按真假决定取哪一个，再把那个原值交出来。

| 运算符 | 从左往右返回什么 |
|---|---|
| `&&` | 第一个假值；全是真值就返回最后一个 |
| `\|\|` | 第一个真值；全是假值就返回最后一个 |

```js
"a" && "b"     // => "b"
0 && "b"       // => 0
"a" || "b"     // => "a"
0 || "默认"     // => "默认"
```

由此产生短路：左边已能定结果时右边不再执行。常用 `y && y.toString()` 避免对 `null` 调用方法，也常用 `nickname || "匿名用户"` 设置默认值。

因为 `&&` 优先级高于 `||`，混合使用时必须加括号，否则结合顺序会和预期不同。

### 自增自减

`++`、`--` 每次让变量增减 1，且只能用于变量，写成 `1++` 会报错。单独成句时前置与后置没有区别，一旦参与表达式就分道扬镳。

```js
var a = 10
console.log(a++)   // => 10   先返回旧值，再自增
console.log(a)     // => 11

var b = 10
console.log(++b)   // => 11   先自增，再返回新值
```

后置 `n++` 先用后变，前置 `++n` 先变后用。因为表达式从左往右逐个求值，连写成 `++n + n++ + ++n` 时每一步的返回值都不同，结果很难一眼算准。

```js
var n = 10
var res = ++n + n++ + ++n
console.log(n, res)   // => 13 35
```

连写的复杂表达式应拆开写，能读懂比写得短重要；而且拆开后每一步的变量变化都清楚，也便于调试。
