第 09 章 · 面向对象

继承与多态： 一套代码，管一群对象

继承解决「重复」，多态解决「扩展」。当你能写出一句 animal.speak() 就自动调度到狗叫或猫叫时，你才真正摸到了面向对象的门。这两个机制也是所有框架和设计模式的底层原理。

9.1继承：表达「是一个」的关系

Dog 是一个 Animal，所以 Dog 可以继承 Animal。

继承的语法是 class 子类 extends 父类。语义上它表达的是 is-a：狗是一种动物，所以狗自动继承动物的一切共性。反例是「汽车有发动机」，这是 has-a，应该用组合（把发动机作为字段），而不是继承。

Java 只支持单继承：一个类只能有一个直接父类。这是为了避开 C++ 菱形继承的二义性问题——如果 A 同时继承 B 和 C，而 B、C 又有同名方法，调用时该用哪个？Java 用单继承 + 多接口实现绕开了这个难题。

子类继承了什么

继承父类非 private 的成员变量和方法；不继承构造器（但必须调用）；父类的 private 成员虽然存在于子类对象中，但子类不能直接访问，只能通过 getter。所有类最终都继承 Object。

方法重写（Override）是继承的关键动作：子类提供与父类「方法名相同、参数列表相同」的新实现。重写有三条约束——访问权限不能变小、返回值必须相同或是其子类型、不能抛出更宽的受检异常。掌握这些约束的最简单方式，就是永远加 @Override，让编译器替你检查。

对比项重写 Override重载 Overload
发生位置子类与父类之间同一个类中
方法名相同相同
参数列表必须相同必须不同
绑定时机运行期，看真实对象编译期，看参数类型
与多态的关系多态的前提无关

9.2super 与构造顺序

子类对象里一定先有一个完整的父类部分。

super 有两个用途：一是访问父类被重写的方法或被子类遮蔽的字段（super.speak()），二是在子类构造器第一行调用父类构造器（super(name, age)）。

如果不写 super(...)，编译器会自动插入无参的 super()。所以父类如果没有无参构造器，子类必须显式调用有参版本，否则编译失败。这是新人最常遇到的继承报错。

子类构造器java
public Dog(String name, int age) {
    super(name, age);    // 必须是第一行
}

@Override
public void speak() {
    super.speak();       // 先执行父类逻辑
    System.out.println(getName() + " 汪汪叫");
}

完整的初始化顺序是：父类静态块 → 子类静态块 → 父类实例块 → 父类构造器 → 子类实例块 → 子类构造器。静态块只在类第一次加载时执行一次，所以创建第二个对象时不再出现。这个顺序解释了为什么「在父类构造器里调用被子类重写的方法」是危险操作——此时子类的字段还没初始化。

this() 与 super() 只能选一个

两者都要求写在构造器第一行，所以同一个构造器里不可能同时出现。如果一组构造器既想复用本类逻辑又需要调父类，只能在「最底层的那个构造器」里调 super。

9.3权限修饰符：继承中的边界

protected 是专为继承设计的，但滥用它会破坏封装。

四种修饰符的可见范围在上一章已经列过。放到继承场景里，需要特别记住两条：private 成员不被继承（虽然对象里存在），默认修饰符的成员跨包时连子类也访问不到（这一点常被误认为 protected 的行为）。

父类成员修饰符子类是否继承子类能否直接访问
public继承能
protected继承能（跨包也可以）
默认（同包）同包子类继承同包能，跨包不能
private不继承不能，只能通过 getter
static 方法被隐藏而非重写能，但不参与多态
final 方法继承不能重写

实践建议是：字段一律 private，通过 protected 或 public 的方法给子类访问能力。直接把字段设为 protected 看似方便，实则让子类可以随意修改父类状态，父类再也无法保证自己的不变式——这是封装被破坏的典型场景。

9.4多态：同一个调用，不同实现

编译时看左边，运行时看右边。

多态需要三个条件同时满足：有继承关系、子类重写了父类方法、父类引用指向子类对象。三者缺一不可——少了重写，调用的还是父类实现；少了父类引用，就没有「统一入口」。

多态的最小示例java
Animal a1 = new Dog("旺财", 3);
Animal a2 = new Cat("咪咪", 2);

a1.speak();    // 旺财 汪汪叫
a2.speak();    // 咪咪 喵喵叫

// 统一处理，新增类型不用改这段代码
for (Animal a : new Animal[]{a1, a2}) a.eat();

它的价值在于解耦。写 feed(Animal animal) 时，你不需要知道将来会有多少种动物；新增一个 Bird 类，这个方法一行都不用改。这就是「对扩展开放、对修改关闭」的开闭原则，也是框架能用一套代码调度无数业务实现的原因。

但多态不是万能的。有三类成员不参与动态绑定：成员变量（按编译期类型解析）、静态方法（属于类，不随对象变）、private 方法（不可重写）。所以 a1.age 取到的是父类的字段，即使子类也定义了同名 age。

动态绑定是怎么实现的

每个对象头里保存着指向自己类元数据的指针，类元数据里有一张「虚方法表」，记录了每个可重写方法的实际入口。调用实例方法时，JVM 顺着这张表找到真实实现，因此运行期才知道该执行谁的代码。

9.5向上与向下转型

向上自动且安全，向下必须确认身份。

向上转型是把子类对象赋给父类引用，自动完成、绝对安全，代价是「看不到子类特有的方法」——因为编译器只认父类类型。向下转型是把父类引用转回子类类型，必须强制转换，且只有对象的真实类型匹配时才成功。

转型与异常java
Animal a = new Dog("旺财", 3);
// a.guard();                 // 编译错误：Animal 没有 guard

Dog d = (Dog) a;              // 向下转型，成功
d.guard();

Animal cat = new Cat("咪咪", 2);
Dog wrong = (Dog) cat;        // ClassCastException

为什么需要向上转型？因为它让方法参数、集合、返回值都能面向抽象编写。List<Animal> 可以装任何子类，调用方不需要为每种动物写一个重载方法。这是「面向接口/父类编程」的具体体现。

9.6instanceof 与 final

转型前先验身份，扩展前先想清楚要不要封死。

instanceof 用来判断对象的真实类型是否是某个类（或其子类）。它对 null 永远返回 false，不会抛异常，所以在转型前用它做保护是最安全的做法。Java 16 之后支持模式匹配：if (a instanceof Cat c) 一步完成判断与绑定，省掉重复强转。

模式匹配java
for (Animal a : animals) {
    if (a instanceof Dog d) d.guard();
    else if (a instanceof Cat c) c.catchMouse();
}

final 有三种用法，含义各不相同：修饰变量表示只能赋值一次；修饰方法表示不能被子类重写；修饰类表示不能被继承。String、Integer 都是 final 类，目的就是保证不可变性与行为不被篡改。

一个常见误解：final List<String> list = new ArrayList<>(); 之后仍然可以 list.add("a")。final 锁住的是「引用不再指向别的对象」，而不是对象内部状态。想要真正不可变，需要用 Collections.unmodifiableList() 或 List.of()。

小结这一章真正要记住的

Key takeaways

  1. 继承表达 is-a，has-a 应该用组合。 Java 只支持单继承，避免二义性。
  2. 重写要求同名同参、权限不变小、返回值兼容。 永远加 @Override 让编译器检查。
  3. 子类构造器必须先调父类构造器。 顺序：父静态 → 子静态 → 父实例 → 父构造 → 子实例 → 子构造。
  4. protected 是给继承用的，但字段仍应 private + 方法暴露。
  5. 多态三前提：继承、重写、父类引用指向子类对象。 成员变量、静态方法、private 方法不参与多态。
  6. 向上转型自动安全，向下转型必须先用 instanceof 验类型。
  7. final 修饰变量锁引用、修饰方法禁重写、修饰类禁继承。 它不保证对象内容不可变。

自测检查一下你真的懂了吗

Java 支持多继承吗？接口呢？为什么这么设计？
类只支持单继承，避免菱形继承时同名成员产生二义性；接口支持多实现，因为接口方法默认是抽象的，冲突时由实现类显式指定。
子类构造器为什么必须先调用父类构造器？不写 super() 会怎样？
子类对象包含父类部分，必须先完成父类初始化。不写时编译器自动插入无参 super()；若父类没有无参构造器就编译失败，必须显式调 super(参数)。
Animal a = new Dog(); a.speak(); 执行哪个 speak？如果 Dog 没重写呢？
重写了就执行 Dog 的版本；没重写则继承父类实现，执行 Animal 的 speak。绑定发生在运行期，看堆中真实对象类型。
什么情况下向下转型会抛 ClassCastException？怎么避免？
对象真实类型不是目标类型（或其子类）时强转会抛。避免方式：先用 instanceof 判断，或用 Java 16+ 的模式匹配一步完成。
为什么成员变量不参与多态？
字段访问在编译期就按变量声明类型解析，没有虚方法表机制。所以 Animal a = new Dog() 中 a.age 取的是 Animal 定义的字段，即使 Dog 也声明了同名 age。
