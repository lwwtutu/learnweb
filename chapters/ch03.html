运算符与方法： 从「能存」到「能算」

运算符决定了表达式怎么算，方法决定了逻辑怎么拆。这一章不追求把所有符号列一遍，而是把最容易出错的几个点讲透：整数除法、取模符号、自增时机、短路求值、参数传递，以及「为什么要有方法」。

3.1算术运算符：两个结果由类型决定

同样的除法，操作数类型不同，结果可能差很远。

加减乘除没什么好说的，Java 的坑集中在两处。第一，整数除法直接截断：7 / 2 得 3 而不是 3.5，因为两边都是 int，编译器不会「猜」你想要小数。想得到 3.5，必须让至少一边是浮点。第二，取模结果的符号跟随被除数：-7 % 3 是 -1，7 % -3 是 1，这跟数学里「余数总为正」的直觉不同。

除法与取模java
System.out.println(7 / 2);          // 3
System.out.println(7 / 2.0);        // 3.5
System.out.println(-7 % 3);         // -1
System.out.println(7 % -3);         // 1
System.out.println(1.0 / 0);        // Infinity，不抛异常

这个特性在写业务代码时非常危险。计算百分比时如果先做整数除法，会得到 0：1 / 2 * 100 是 0，正确写法是 1 * 100 / 2 或 1.0 / 2 * 100。计算平均值、打折价、及格率时都要先检查这一点。

另一个细节是 + 的双重身份：两边都是数值时做加法，只要有一边是字符串就变成拼接。"结果：" + 1 + 2 得到「结果：12」，而 "结果：" + (1 + 2) 才是「结果：3」——因为从左到右依次计算，一旦遇到字符串，后面全部按字符串处理。

3.2赋值与自增：两个隐藏的转换

+= 自带强转，++ 的前后位置决定取值时机。

复合赋值运算符 +=、-=、*= 看起来只是简写，其实额外做了一件事：隐含强制类型转换。所以 byte b = 10; b += 5; 能通过编译，而 b = b + 5; 不行——前者等价于 b = (byte)(b + 5)。

自增自减的坑在于「什么时候取值」。i++ 是先取当前值参与运算，再自增；++i 是先自增，再取值参与运算。单独成行时两者没区别，一旦嵌进表达式，结果就不同了。

自增的求值时机java
int i = 5;
int m = i++;    // m = 5，之后 i = 6
int n = ++i;    // i 先变 7，n = 7

int j = 1;
j = j++;        // 陷阱：先把 1 暂存，j 变 2，又把 1 赋回
System.out.println(j);   // 1

面试喜欢考 i++ + ++i 这类题，但工程上应当禁止把自增写在复杂表达式里。可读性差、容易出错，拆成两行不会有任何性能损失。

3.3关系与逻辑：短路是安全网

&& 和 & 的差别不只是效率，而是会不会崩。

关系运算符的结果一定是 boolean，这没什么可讲的。逻辑运算符里真正重要的是短路：&& 左边为 false 时不计算右边，|| 左边为 true 时不计算右边；而 & 和 | 无论左边如何都会算完两边。

这个特性被广泛用于防御性判断。判断字符串是否为空时，必须先判 null 再调方法，否则 null 调用 .equals() 或 .length() 会直接抛空指针。短路让「先判空、再使用」成为可能。

短路与常量前置java
String user = null;

// 左边为 false，右边不会执行，因此不会 NPE
if (user != null && user.length() > 3) { ... }

// 常量前置：即使 user 为 null 也不会崩
System.out.println("admin".equals(user));

还有一个必须养成的习惯：比较两个字符串内容时写成 "admin".equals(user) 而不是 user.equals("admin")。前者在 user 为 null 时返回 false，后者会抛异常。这条规则叫「常量前置」，能省掉大量判空代码。

3.4三元与位运算：两个特定场景的工具

三元是 if 的表达式版，位运算直接操作二进制。

三元运算符 条件 ? 值1 : 值2 的价值在于它返回一个值，可以直接赋给变量或作为参数，而 if 是语句，不能这样用。简单的二选一赋值用三元更紧凑，但嵌套超过两层就该改回 if，否则可读性会急剧下降。

位运算在日常业务里出现频率不高，但在三种场景中无可替代：权限标记（用二进制位表示读、写、执行）、状态压缩（一个 int 存 32 个开关）、性能敏感的计算（左移 1 位等于乘 2）。理解 & 与 | 在二进制层面的含义，这些用法就自然懂了。

用位运算表示权限java
final int READ = 1;      // 0001
final int WRITE = 2;     // 0010
final int EXEC = 4;      // 0100

int permission = READ | WRITE;              // 0011
boolean canRead = (permission & READ) != 0;   // true
boolean canExec = (permission & EXEC) != 0;   // false

右移分两种：>> 是算术右移，左边补符号位，负数移位后还是负数；>>> 是逻辑右移，左边一律补 0，负数会被移成一个很大的正数。这个区别在处理哈希值、二进制协议时很关键。

3.5优先级：不需要背，需要加括号

记住三条主线，其余靠括号表达意图。

Java 的优先级有十几级，全背下来性价比极低。实际需要记住的只有三条：算术 > 关系 > 逻辑 > 赋值；&& 优先级高于 ||；赋值结合性从右向左，所以 a = b = c 合法。

最容易被误读的是 2 + 3 + "x" + 4 + 5，结果是 5x45 而不是 5x9——因为 + 是左结合的，先算完 2+3，遇到字符串后全部转为拼接。遇到这类表达式，加括号不是能力不足，而是专业素养：代码是给人读的，编译器不在乎你怎么写。

3.6方法：把逻辑切成可复用的块

方法的本质是「命名 + 参数 + 返回值」三件事的封装。

没有方法时，同样的逻辑要在多处复制粘贴；改一处就得改十处，漏一处就出 bug。方法解决三个问题：复用（写一次调多次）、抽象（调用方只需知道「做什么」，不必关心「怎么做」）、可测试（输入输出明确，能单独验证）。

方法签名

方法签名 = 方法名 + 参数列表（类型、个数、顺序）。返回类型和参数名不属于签名。这解释了为什么重载不能只靠返回值区分，也解释了编译器如何决定调用哪个方法。

方法的四个组成部分java
public static int add(int a, int b) {
    return a + b;
}
// public static  —— 修饰符：谁能调用、属于类还是对象
// int            —— 返回值类型，void 表示不返回
// add            —— 方法名，动词开头，小驼峰
// (int a, int b) —— 形参列表，调用时传入实参

两个规范值得从第一天就遵守。一是方法只做一件事：名字里出现「和」「并且」时，通常该拆成两个方法。二是所有分支都要有返回值：有返回值的方法，每条执行路径都必须 return，否则编译不通过——这不是啰嗦，而是强迫你想清楚每种情况。

3.7重载与参数传递

重载看参数，传参只看值。

重载允许同一个类里有多个同名方法，只要参数列表不同。编译器在编译期就根据实参的类型和个数选定调用哪个版本，这叫静态绑定。所以重载与多态无关，与返回值也无关。

参数传递更容易误解。Java 里只有值传递：基本类型传的是值的副本，引用类型传的是地址的副本。这带来两个可预期的结果——改基本类型不影响原变量；通过引用改对象内容会影响原对象，但让引用指向新对象不会。

值传递的两种表现java
static void change(int n) { n = 100; }             // 改不动原值
static void modify(int[] a) { a[0] = 99; }         // 改得动内容
static void reassign(int[] a) { a = new int[]{7}; } // 改不动引用

int x = 10; change(x);          // x 仍是 10
int[] arr = {1,2,3}; modify(arr);   // arr[0] = 99
reassign(arr);                  // arr 仍指向原数组
为什么理解这点很重要

它决定了你写方法时的接口设计：想「修改调用方的变量」，就不能靠传基本类型，要么返回新值，要么传入可变对象（数组、集合、自定义对象）。这也是为什么工具类方法通常返回结果而不是改参数。

3.8Scanner：让程序能对话

交互式程序的入口，但有两个必须知道的坑。

Scanner 包装了标准输入流，提供 nextInt()、nextDouble()、nextLine() 等方法按类型读取。它的工作方式是「跳过空白、读取一个 token」，理解这一点才能解释下面两个问题。

坑一：nextInt 后接 nextLine 会读到空串。 因为 nextInt 只读走数字，行尾的换行符还留在缓冲区，nextLine 一看到换行就直接返回空字符串。坑二：输入格式不对会抛异常。 用户输入字母而你调 nextInt，会抛 InputMismatchException；生产代码里要么先校验，要么统一用 nextLine 读整行再解析。

读取姓名与年龄java
Scanner sc = new Scanner(System.in);
System.out.print("姓名：");
String name = sc.nextLine();
System.out.print("年龄：");
int age = Integer.parseInt(sc.nextLine());   // 统一按行读，再解析
sc.close();

注意最后要 close() 释放资源。在真实项目里，Scanner 更多用于教学和命令行工具；Web 应用的输入来自 HTTP 请求参数，但「读取 → 校验 → 转换」这套思路是完全一致的。

小结这一章真正要记住的

Key takeaways

  1. 整数除法截断、取模符号跟随被除数。 算比例时先乘后除，或提前转成浮点。
  2. += 隐含强制转换，++ 的位置决定取值时机。 不要把自增塞进复杂表达式。
  3. && 短路是防御性编程的基础。 「先判空再使用」和「常量前置」能消掉大半空指针。
  4. 三元返回一个值，if 只是一条语句。 二选一赋值用三元，超过两层嵌套改回 if。
  5. 优先级不必背，括号表达意图。 记住「算术 > 关系 > 逻辑 > 赋值」即可。
  6. 方法签名 = 名字 + 参数列表。 重载靠它区分，与返回值无关。
  7. Java 只有值传递。 引用类型传的是地址副本，能改内容、改不了指向。
  8. Scanner 按 token 读取，nextInt 后要处理换行。 统一用 nextLine + 解析更稳。

自测检查一下你真的懂了吗

7 % -3 和 -7 % 3 分别等于多少？
1 和 -1。取模结果的符号跟随被除数（左边的数）。
int i = 5; int r = i++ + ++i; 执行后 i 和 r 是多少？
i = 7，r = 12。i++ 先取 5（i 变 6），++i 先自增到 7 再取值，5 + 7 = 12。
为什么推荐 "admin".equals(user) 而不是 user.equals("admin")？
user 为 null 时，后者会抛 NullPointerException，前者不会。这叫「常量前置」写法，配合 && 短路可以让判空逻辑更简洁。
方法重载能不能只靠返回值类型区分？为什么？
不能。调用 sum(1, 2) 时编译器无法从上下文推断你期望的返回类型，所以重载必须参数列表不同。签名不包含返回值。
把数组传进方法修改元素，调用方能看到变化吗？把方法内的引用改为新数组呢？
改元素能看到——两个引用指向同一堆对象；改成新数组看不到——那只是局部变量（地址副本）重新指向，原引用未变。
