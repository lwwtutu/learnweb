数组： 第一件真正的数据容器

变量一次只能存一个值，处理 50 个成绩就要 50 个变量——这不现实。数组把同类型的多个值排成一排，用下标统一访问。它的内存模型非常干净，理解了它，后面的集合、字符串、二维表格都不再神秘。

5.1数组的本质：一块连续的内存

长度固定、类型统一、内存连续——三个特征决定了它的全部优缺点。

声明 int[] scores = new int[5]; 时，JVM 在堆上划出一块连续的 20 字节（5 个 int × 4 字节），栈上的 scores 只保存这块区域的首地址。所谓「下标」，本质是偏移量：访问 scores[3] 时，JVM 用「首地址 + 3 × 4 字节」直接算出位置，一步到位。

因为地址能算出来，所以数组的随机访问是 O(1)；因为要连续，所以长度一旦确定就不能变。
三个特征带来的三个结论

类型统一：每个元素占的字节数相同，才能用乘法算偏移，所以一个数组只能放一种类型。

长度固定：创建时就分配好整块空间，想「变长」只能新建一个更大的数组再搬过去。

内存连续：随机访问极快，但中间插入/删除元素需要移动后面所有数据，代价高。

创建数组有两种方式。静态初始化用于已知所有元素的情况，直接把值写出来；动态初始化用于只知道长度、值稍后填入的情况，此时元素会被赋予默认值——int 是 0，double 是 0.0，boolean 是 false，引用类型是 null。

两种初始化java
int[] a = {88, 92, 76};            // 静态初始化
int[] b = new int[]{88, 92, 76};   // 完整写法

double[] c = new double[5];        // 动态初始化，全 0.0
String[] d = new String[2];        // 全 null

System.out.println(a.length);      // 3，length 是属性，没有括号
length 不是方法

数组用 arr.length，字符串用 str.length()，集合用 list.size()。三者形式不同，混用是最常见的编译错误之一。

5.2遍历与两个必考异常

合法下标永远是 0 到 length-1。

遍历数组有两种写法。普通 for 能拿到下标，适合需要位置信息的场景（找最大值所在位置、首尾交换）；增强 for（for-each）只能读值，适合单纯累加、打印。增强 for 更简洁，但拿不到下标，也不能在遍历时修改元素（修改的只是副本）。

数组操作中的异常几乎只有两种，且原因都很明确：

  • ArrayIndexOutOfBoundsException：下标小于 0 或大于等于 length。典型错误是把 i <= arr.length 写成了小于等于。
  • NullPointerException：数组变量是 null 却去访问 arr[0] 或 arr.length。使用前必须判空。
求最大值java
int max = arr[0];                    // 用首元素做基准，别用 0
for (int i = 1; i < arr.length; i++) {
    if (arr[i] > max) max = arr[i];
}

这段代码有个容易忽略的细节：基准值为什么取 arr[0] 而不是 0？如果数组全是负数，用 0 做基准会得到错误结果 0。这是「边界数据」思维的第一次体现——写逻辑时先想极端情况。

5.3二维数组：数组的数组

它不是矩阵，而是「每个元素都指向一个一维数组」的数组。

理解这一点，很多现象就顺了：matrix.length 是行数，matrix[i].length 是第 i 行的列数，两者可以不同——这就允许了「不规则二维数组」。声明 new int[3][] 时，只创建了 3 个「行引用」，每行还是 null，必须再逐行分配。

不规则二维数组java
int[][] grid = new int[3][];        // 3 行，列未定
grid[0] = new int[]{1};
grid[1] = new int[]{2, 3};
grid[2] = new int[]{4, 5, 6};

// System.out.println(grid[0][1]); // 越界：第 0 行只有 1 个元素

二维数组最适合描述「有行有列」的数据：座位表、棋盘、成绩单、图像像素。遍历的固定套路是外层走行、内层走列，内层条件必须用 matrix[i].length，写成 matrix[0].length 遇到不规则数组就会越界。

5.4Arrays 工具类：别重复造轮子

排序、查找、比较、填充、拷贝，JDK 都写好了。

java.util.Arrays 提供了一组静态方法。日常开发中，除非是为了练习算法，否则不应该手写排序——Arrays.sort() 用的是双轴快排，经过大量优化，比你自己写的稳定得多。

方法作用注意
toString(arr)转成可读字符串直接打印数组只会得到地址
sort(arr)升序排序原地修改，不返回新数组
binarySearch(arr, key)二分查找必须先排序，找不到返回负数
equals(a, b)比较内容数组的 == 比的是地址
fill(arr, v)填充原地修改
copyOf / copyOfRange拷贝返回新数组，长度可不同
deepToString(m)二维数组转字符串普通 toString 只会打印地址
为什么打印数组是一串乱码

数组没有重写 toString()，默认实现是「类型@哈希码」，所以 [I@1b6d3586 其实是 [I（int 数组）+ 地址。想看到内容，必须用 Arrays.toString()。

5.5冒泡排序：理解排序的入口

思想很简单：相邻两两比较，大的往后冒。

一轮扫描下来，最大的元素一定被推到末尾；第二轮再对剩下的部分做同样的事，第二大的就到了倒数第二位。n 个元素最多需要 n-1 轮，每轮比较次数递减，所以内层条件是 j < length - 1 - i。

这个算法有两点值得学。一是优化：如果某一轮一次交换都没发生，说明已经有序，可以提前结束，最好情况从 O(n²) 降到 O(n)。二是稳定性：只有「大于」才交换，相等元素不会换位，所以冒泡是稳定排序。

冒泡排序核心java
for (int i = 0; i < arr.length - 1; i++) {
    boolean swapped = false;
    for (int j = 0; j < arr.length - 1 - i; j++) {
        if (arr[j] > arr[j + 1]) {
            int t = arr[j]; arr[j] = arr[j + 1]; arr[j + 1] = t;
            swapped = true;
        }
    }
    if (!swapped) break;      // 已有序，提前退出
}

它的价值不在实用，而在于演示「算法是怎么被设计出来的」：先想清楚每一轮能得到什么确定的结果，再把它重复 n-1 次。理解了这个思路，选择排序、插入排序都能自己推出来。

5.6二分查找：每次砍掉一半

前提是有序，核心是不断收缩区间。

线性查找最坏要看 n 次，二分查找每次比较后都能排除一半，所以最多 log₂n 次——100 万条数据只需约 20 次比较。代价是必须先排序，而且数据要支持随机访问（数组可以，链表不行）。

二分查找核心java
int left = 0, right = arr.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;   // 防溢出写法
    if (arr[mid] == target) return mid;
    else if (arr[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return -1;

三个细节决定这段代码是否正确：循环条件是 <=（区间只剩一个元素时还要比较）；更新是 mid±1（mid 已经比较过，不必再包含）；mid 用减法算，避免 left+right 溢出成负数。二分查找是「边界处理」最好的练习素材，写错一个符号就会死循环或漏掉元素。

5.7拷贝与扩容：数组不能变长

想「变大」，只能新建一个更大的，再把数据搬过去。

直接赋值 int[] b = a; 不是拷贝，只是给同一个数组起了个别名——两个变量保存同一个地址，改一个另一个也变。真正的拷贝要分配新空间再复制内容，有三种方式：Arrays.copyOf（最简洁）、System.arraycopy（性能最好，可指定区间）、clone()（返回 Object，需强转）。

扩容的标准写法java
int[] grown = new int[arr.length * 2];
System.arraycopy(arr, 0, grown, 0, arr.length);
arr = grown;                       // 让原引用指向新数组

这段代码就是 ArrayList 扩容的雏形：底层维护一个 Object 数组，装不下时按 1.5 倍扩容并复制元素。理解了数组扩容的代价，就能明白为什么「频繁在中间插入元素」很慢，也就知道什么时候该用链表。

为什么是 1.5 倍不是 2 倍

2 倍增长在长期看会浪费更多内存，1.5 倍在「扩容次数」和「空间浪费」之间取得了折中。这是工程上的经验值，不是数学定理。

小结这一章真正要记住的

Key takeaways

  1. 数组 = 连续内存 + 统一类型 + 固定长度。 连续带来 O(1) 随机访问，固定带来扩容成本。
  2. length 是属性，不是方法。 合法下标是 0 到 length-1。
  3. 两种异常要对得上原因。 越界是下标超范围，NPE 是数组变量为 null。
  4. 二维数组是「数组的数组」。 行数用 matrix.length，列数用 matrix[i].length。
  5. 优先用 Arrays 工具类。 排序、查找、比较、拷贝都有现成实现。
  6. 冒泡是 O(n²) 稳定排序，二分是 O(log n) 但要求有序。 两者的价值都在于训练边界思维。
  7. 赋值是别名，拷贝是新数组。 扩容需要三步：新建、复制、改指向。

自测检查一下你真的懂了吗

int[] a = new int[3]; 中 a.length 是多少？a[3] 呢？
length 是 3，合法下标是 0~2；访问 a[3] 会抛 ArrayIndexOutOfBoundsException。
为什么数组的随机访问是 O(1)？换成链表还成立吗？
因为元素连续存放且大小相同，可以用「首地址 + 下标 × 元素大小」直接算出地址。链表节点分散在内存中，必须从头逐个遍历，所以是 O(n)。
Arrays.binarySearch 为什么必须先排序？数组无序会怎样？
二分依赖有序来判断目标在哪一半。无序时比较结果没有意义，会返回错误下标或负数，而且不会报错——这是很隐蔽的 bug。
int[] b = a; 之后修改 b[0]，a[0] 会变吗？怎么做到互不影响？
会变，这只是别名。想互不影响必须真正拷贝：Arrays.copyOf(a, a.length) 或 System.arraycopy。
二维数组 int[][] m = new int[3][]; 能直接用 m[0][0] 吗？
不能。只分配了 3 个行引用，每行还是 null，访问会抛 NullPointerException。必须先 m[0] = new int[4];。
