**必须做到：**

1. **保留知识逻辑与讲解脉络**：章内小节的先后顺序、概念引入的因果关系、先讲什么后讲什么，必须与原笔记一致。例如「数据类型」先分两大类、再逐个讲 5 种基本类型、最后引出隐式类型转换，这个顺序不能打乱。

3. **删除多余内容**，一律删掉：

   - 自问自答式的铺垫、「你可能要问」「我们来看」等口语水分。
4. **结构化呈现（v2 最重要的硬性要求）**：
   - 每章拆成 **3–6 个 `###` 小节**，必要时用 `####` 再分；**一个小节只讲一个知识点**。
   - **严禁把 3 个及以上独立概念塞进同一个段落**。例如讲 5 种基本数据类型，必须写成 5 个独立小节（或「每类型一小节 + 一张对照表」），不能揉成一段文字。
   - **单个段落不超过约 120 字 / 4 行**；信息多就改成分点列表、表格或拆小节。
   - 每个小节推荐节奏：**一句话定义 → 1–3 句解释「为什么这样 / 怎么理解 / 什么时候用」 → 代码块或表格 → 结果与易错点**。
   - 必须有解释性语句，**不能只罗列结论**。读者要能看懂概念，而不是背下一串短语。

     3. `### 关键知识点` —— 用 `- ` 分点列出 2–4 个关键点，**每点用 1–3 句解释「为什么这样做 / 换成别的会怎样」**，不能只写一句结论。必要时可加一张小型对照表。
   - 案例章总量 **500–900 字**（含代码），单段文字仍不超过 120 字。
   - **不要把完整代码切成五六段散落在各小节里**；学习者需要一次看到全貌，再回头对照注解。
   - 混合型章节（如「字符串基础与统计案例」「继承案例」）也按此结构，但 `需求与思路` 里先用几句话交代本章涉及的知识点，再给案例代码。
6. **篇幅（普通章）**：正文 **600–1200 字**（中文字符计），核心概念章（数据类型、数组方法、作用域、原型、事件流、Promise 等）可到 **1500 字**。每章 2–4 个代码块 / 表格。
   - 注意：篇幅放宽是为了把知识点**讲开、讲透、拆散**，不是允许注水或重复。

8. **多参考原笔记**：改写前把原笔记该章完整读完，把其中被 v1 遗漏的**关键细节、对比、由来、使用场景、易错点**补回来。判断标准：一个只学到这里的人，读完能否真正理解并会用。
9. **语气**：讲授式、干净、明确。不要用「同学们」「接下来让我们一起」这类课堂口语，不要煽情，不要 emoji 堆砌。
10. **语言**：简体中文；API 名、关键字、代码保持英文原样。

### Number：整数和小数共用一个类型

JS 不区分整数与小数，两者都是 `number`。这样设计让数值运算不必先判断类型，
代价是所有数字都按双精度浮点存储，会有 `0.1 + 0.2` 这类精度误差。

```js
var age = 18
var price = 12.5
console.log(typeof age, typeof price)   // => "number" "number"
```

进制用前缀区分，`e` 表示 10 的幂：

| 写法 | 含义 | 值 |
|---|---|---|
| `2e3` | 2 × 10³ | 2000 |
| `0xff` | 十六进制 | 255 |
| `0b11` | 二进制 | 3 |
| `0o77` | 八进制（推荐） | 63 |

> ⚠️ 老式 `077`（0 开头）在严格模式下会报错，一律写 `0o77`。

#### NaN：运算失败的结果

除法、转换失败不会抛错，而是返回 `NaN`。它表示"不是有效数字"，
但 `typeof` 仍是 `number`——因为它属于数字运算的结果。

```js
console.log(10 / "abc")    // => NaN
console.log(typeof NaN)    // => "number"
console.log(NaN === NaN)   // => false
console.log(isNaN(NaN))    // => true
```

`NaN` 是唯一不等于自身的值，所以判断要用 `isNaN()`，不能用 `===`。

### 字段说明

- `===PART===` 段：`id`、`order`、`title`、`range`、`desc` 五个字段，各占一行，冒号后一个空格。
  - `range` 用 `–`（en dash）连接，如 `001–017`。
- `===CH===` 段：`no`、`title`、`lessons`、`summary`、`points` 五个字段。
  - `no` 是原笔记的章号（**不要重新编号**，保留 78→90、125→133 这样的跳号）。
  - `lessons` 是本章对应的 material 文件夹编号范围，如 `019–020` 或 `008`；从笔记的「对应代码」或目录表推断。
  - `points` 用 ` || ` 分隔，3–5 条，每条 10–28 字，是本章最值得记住的结论（不是标题复述）。
- `===BODY===` 之后到下一个 `===CH===`（或文件结尾）是正文，**不再写任何元信息**。

### 正文可用的 Markdown 子集（渲染器只支持这些，不要用别的）

- `### 三级标题`、`#### 四级标题`
- 普通段落；`**加粗**`；`` `行内代码` ``

- **禁止**：图片、链接、HTML 标签、行内公式、脚注、`===` 开头的行、`# 一级标题`、`## 二级标题`
