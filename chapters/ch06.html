字符串与正则： Java 里最重要的一个类

String 是面试出现频率最高的类，没有之一。它不可变、有常量池、== 和 equals 表现不同、拼接有性能陷阱。这些不是零散的知识点，而是同一个设计决策连锁产生的后果——想通这一点，整章就通了。

6.1不可变：一个决定，连锁反应

String 一旦创建，内容永远不变；所有「修改」都是新建。

String 内部用一个 private final 的字符数组保存内容，且不提供任何修改该数组的方法。所以 toUpperCase()、replace()、concat() 看起来在改字符串，实际都返回了一个新对象，原对象原封不动。

这个设计不是为了省事，而是为了解决四个真实问题：

  • 可以安全共享。 常量池里同一个 "hello" 能被无数变量引用，谁都不能改它，所以不需要复制。
  • 天然线程安全。 多线程读写同一个 String 不需要加锁。
  • hashCode 可以缓存。 内容不变，哈希值算一次就够，作为 HashMap 的键非常高效。
  • 传参安全。 把字符串传给方法，不用担心对方把它改掉。
字符串常量池

JVM 在堆中维护一块区域专门存放字符串字面量。用字面量方式创建时，先查池里有没有内容相同的对象：有就复用，没有才新建。所以 String a = "hi"; String b = "hi"; 中 a 和 b 指向同一个对象。

三种创建方式的差别java
String s1 = "hello";                 // 复用常量池
String s2 = "hello";                 // 复用同一个对象
String s3 = new String("hello");     // 强制在堆中新建

System.out.println(s1 == s2);        // true
System.out.println(s1 == s3);        // false
System.out.println(s1.equals(s3));   // true

还有一个细节："he" + "llo" 这种编译期常量折叠，编译器会直接合成 "hello"，结果仍然指向常量池；但如果拼接里有变量，就只能在运行期新建对象。这解释了为什么两道看起来一样的题，答案可能不同。

典型组合用法java
String text = "  Hello, Java World!  ";
String clean = text.trim();
clean.substring(0, 5);              // "Hello"
clean.replaceAll("[^a-zA-Z]", "");  // 去掉非字母
"张三,18,男".split(",");             // ["张三","18","男"]
split 的两个坑

① 参数是正则，切 .、|、* 必须转义：split("\\.")，否则 . 会匹配任意字符，整个字符串被切没。② 末尾的连续空串会被丢弃，需要保留时写 split(",", -1)。

6.3== 与 equals：地址和内容的区别

引用类型比较内容，永远用 equals。

== 比较的是变量里的值。对基本类型来说，这个值就是数据本身，所以比较内容；对引用类型来说，这个值是地址，所以比较是否指向同一个对象。String 是引用类型，因此 == 判断不了内容是否相同。

另一个高频问题是 null 与空串的区别。null 表示「没有指向任何对象」，调用任何方法都会崩；"" 是一个长度为 0 的真实对象，可以正常调用方法。判空必须两者都考虑：

安全判空java
public static boolean isBlank(String s) {
    return s == null || s.trim().isEmpty();
}
// 或 Java 11+
return s != null && !s.isBlank();

还有一个容易被忽略的点：String.equals(StringBuilder) 永远返回 false。因为 StringBuilder 没有重写 equals，比较退化成地址比较。需要比较内容时用 contentEquals。

6.4拼接：单行随意，循环必须换

编译器会优化单行拼接，但救不了循环里的 +=。

因为不可变，每次 + 都要创建新的 StringBuilder、复制旧内容、再 toString 成新 String。在循环里做 n 次，总复制量是 1+2+...+n ≈ n²/2。数据量一大，耗时就从毫秒涨到秒。

两种写法的差距java
String s = "";
for (int i = 0; i < 20000; i++) s += i;      // 数百毫秒

StringBuilder sb = new StringBuilder();
for (int i = 0; i < 20000; i++) sb.append(i); // 几毫秒
单行拼接不用改

"姓名：" + name + "，年龄：" + age 编译后会自动变成 StringBuilder 链式调用，性能没问题。只有循环内、或跨多步累积字符串时，才需要手动用 StringBuilder。

6.5StringBuilder 与 StringBuffer

可变字符序列，拼接不产生新对象；一个快，一个线程安全。

两者的 API 几乎一样，区别只在线程安全：StringBuffer 的每个方法都加了 synchronized，多线程共享同一个缓冲区时安全，但单线程下有额外的锁开销。日常开发 99% 的场景用 StringBuilder，只有在确定会被多线程共享时才用 StringBuffer。

特性StringStringBuilderStringBuffer
可变性不可变可变可变
线程安全安全（不可变）不安全安全（加锁）
拼接性能差最好稍慢
典型用途常量、少量拼接单线程大量拼接多线程共享拼接

它的常用方法都返回 this，所以可以链式调用。append 追加、insert 插入、delete 删除、reverse 反转、toString 转回 String。反转这个能力让「回文判断」一行就能写完。

6.6格式化与 join：让输出更规范

对齐、补零、千分位，都靠占位符解决。

String.format 用占位符拼字符串，常用的是 %s（字符串）、%d（整数）、%f（小数）、%c（字符）。在 % 和字母之间可以加宽度与精度：%8.2f 表示总宽 8、保留两位小数，%-8s 表示左对齐、宽度 8，%06d 表示不足 6 位补零。

格式化输出java
String.format("%-8s|%5d|%8.2f", "张三", 18, 92.5);
String.format("订单号：%06d", 42);    // 000042
String.format("%,d", 12345678);       // 12,345,678
String.join(" / ", new String[]{"A", "B"});   // A / B

需要拼接一组数据时，String.join 比手写循环更简洁，也比 StringBuilder 更不容易出错。日志输出、SQL 拼装（虽然不推荐这么干）、CSV 生成都会用到。

6.7正则表达式：描述「什么样的字符串」

校验、提取、替换，三件事一次解决。

正则不是 Java 独有的，它是一套通用的文本模式语言。学习的诀窍是从需求反推符号：要「11 位数字且以 1 开头」，就先写 1，再写 \d{10}，最后加 ^...$ 锚定整串，得到 ^1\d{10}$。

符号含义记忆方式
\d / \w / \s数字 / 字母数字下划线 / 空白d=digit, w=word, s=space
.任意字符（不含换行）通配符
[abc] / [^abc]其中之一 / 除它们之外方括号是集合，^ 是取反
* + ?0 次以上 / 1 次以上 / 0 或 1 次数量修饰
{n,m}n 到 m 次精确数量
^ $行首 / 行尾锚定整串
() |分组 / 或提取用分组，选择用竖线
校验与提取java
"13800138000".matches("1[3-9]\\d{9}");    // true
"a1b22c333".split("\\d+");                // [a, b, c]

Matcher m = Pattern.compile("(\\d{4})-(\\d{2})-(\\d{2})")
                   .matcher("2024-07-11");
if (m.find()) System.out.println(m.group(1));   // 2024

两个 API 的区别值得记住：String.matches() 要求整串完全匹配，适合格式校验；Matcher.find() 只要找到任意一段匹配即可，适合从长文本中提取。用错会导致「明明有却匹配不上」或「部分匹配被当成合法」。

性能提醒

正则在编译阶段有成本。同一个正则需要反复使用时，应提前 Pattern.compile() 成对象复用，而不是每次都调用 String.matches()（它内部每次都会重新编译）。

小结这一章真正要记住的

Key takeaways

  1. String 不可变。 共享安全、线程安全、hashCode 可缓存、传参安全，四个好处都源于此。
  2. 字面量走常量池，new 一定新建。 编译期常量折叠仍指向池中对象，含变量的拼接则在运行期新建。
  3. == 比地址，equals 比内容。 引用类型判内容永远用 equals，并注意 null 的判断。
  4. 循环内拼接用 StringBuilder。 单行拼接交给编译器优化，不用手改。
  5. StringBuilder 快、StringBuffer 安全。 单线程无脑选前者。
  6. split 的参数是正则，特殊字符要转义。
  7. matches 整串匹配，find 局部查找。 校验用前者，提取用后者。

自测检查一下你真的懂了吗

为什么说 String 是不可变的？这种设计带来什么好处？
内部用 private final char[]（Java 9 后是 byte[]）保存内容，不提供修改该数组的方法，所有修改都返回新对象。好处：可安全共享、线程安全、hashCode 可缓存、适合做 Map 的键。
String s = new String("abc"); 创建了几个对象？
最多两个：常量池中的 "abc"（若已存在则复用，不新建）+ 堆中 new 出来的新对象。所以通常回答「1 个或 2 个」。
为什么循环里推荐 StringBuilder 而不是 +=？
String 不可变，每次 += 都要新建 StringBuilder、复制旧内容、再生成新 String，n 次循环总复制量约 n²/2；StringBuilder 在内部数组上追加，必要时扩容，整体 O(n)。
"a.b.c".split(".") 的结果是什么？为什么？
返回空数组（长度 0）。因为参数是正则，"." 表示任意字符，整个字符串被当成一个匹配切走了。正确写法是 split("\\.")。
如何判断一个字符串既不是 null、也不是空串、也不全是空格？
s != null && !s.isBlank()（Java 11+）；旧版本写 s != null && s.trim().length() > 0。
