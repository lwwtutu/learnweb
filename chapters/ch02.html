第 02 章 · 语法地基

基础语法： 类型决定了数据的命运

Java 是强类型语言：每个变量在编译期就必须确定类型，之后能存什么、能算什么、会不会丢数据，全都由它决定。这一章的重点不是背语法，而是理解「类型为什么这么设计」以及「什么时候会悄悄出错」。

约 50 分钟 6 个知识点 3 个必背结论 前置：第 01 章

学完这一章，你应该能够

  • 解释 final 常量的意义与命名规范
  • 判断一个变量在哪些位置可见
  • 说出八种基本类型的字节数与范围
  • 解释引用类型赋值时发生了什么
  • 预判一次类型转换是否安全
  • 解释强制转换为何会溢出

2.1常量与变量：什么该变，什么不该变

常量表达「约定」，变量表达「状态」。

程序里有两类数据。一类会随着运行不断变化，比如账户余额、游戏分数、循环计数，它们用变量。另一类在整个运行期间都不应该变，比如圆周率、一周七天、系统允许的最大登录次数，它们应该用常量。

把「不该变的」写成常量，不只是风格问题。如果代码里到处散落着 3.14 和 3，某天需求变更，你得靠搜索一个个改，漏一个就是 bug；而写成常量后只改一处，编译器会帮你保证一致性。这也是一种把意图写进代码的方式：看到 MAX_LOGIN_COUNT，你立刻知道它不能被改。

final 的语义

final 修饰的变量只能被赋值一次，之后任何修改都是编译错误。它在声明时必须初始化（或在构造器中初始化）。修饰基本类型时值不可变；修饰引用类型时引用不可变，但对象内容仍可修改。

常量写法java
public static final double PI = 3.1415926;
public static final int MAX_LOGIN_COUNT = 3;

final int LIMIT = 100;
// LIMIT = 200;   // 编译错误：无法为 final 变量赋值

按规范，常量名全部大写、单词之间用下划线，一眼就能和变量区分开。加了 static 表示它属于类而不是某个对象，全类共享一份，这是定义常量的标准姿势。

2.2作用域：变量能活多久、能被谁看见

一对大括号就是一个作用域，变量出生在其中，也死在其中。

声明位置不同，变量的身份完全不同。写在类体中、方法外的叫成员变量，它跟着对象走；写在方法或代码块里的叫局部变量，它跟着方法调用的栈帧走。方法一返回，局部变量立刻失效，这也是为什么它不能跨方法使用。

对比项成员变量局部变量
声明位置类体中、方法外方法体、代码块、参数列表
存储位置堆（随对象）栈（随方法调用）
默认值有（0 / 0.0 / false / null）没有，必须先赋值
生命周期对象创建到被回收方法进栈到出栈
可加修饰符public、private、static、final 等只能加 final

作用域遵循两条规则。一是嵌套可见：内层能访问外层，外层看不见内层。二是就近优先：内层声明了同名变量，就会遮蔽外层那个，此时想访问外层必须用 this. 或类名限定。这也是为什么第 08 章讲 this 时，第一个用途就是解决同名冲突。

作用域示例java
int a = 10;          // main 内有效
{
    int b = 20;      // 只在这个代码块内有效
    System.out.println(a + b);
}
// System.out.println(b);   // 编译错误：找不到符号

for (int i = 0; i < 3; i++) { }
// System.out.println(i);   // 编译错误：i 只属于 for
为什么局部变量没有默认值

成员变量随对象分配在堆上，JVM 必须给它一个确定初值，否则对象里会有「未定义」的垃圾数据。局部变量在栈上，编译器可以通过「使用前必须赋值」的检查彻底杜绝未初始化读取，代价更小、更安全。

2.3八种基本类型：为什么分这么细

细分不是为了折磨你，而是内存与精度之间的权衡。

整数有四种宽度、小数有两种精度，本质是在问一个问题：这块数据需要多大范围、多少精度？ 用 byte 存年龄足够，用 int 存不了人口数，用 double 存金额会丢精度。选小了溢出，选大了浪费内存，Java 把选择权交给你。

范围有个统一规律：n 位有符号整数的范围是 -2^(n-1) ~ 2^(n-1)-1。所以 byte（8 位）是 -128~127，short（16 位）约 ±3.2 万，int（32 位）约 ±21 亿，long（64 位）约 ±922 亿亿。记住「1、2、4、8 字节」和这个公式，就不需要死记硬背。

类型字节取值范围默认值什么时候用
byte1-128 ~ 1270文件流、明确范围很小的计数
short2-32768 ~ 327670几乎不用，历史遗留
int4约 ±21 亿0整数的默认选择
long8约 ±9.2×10¹⁸0L时间戳、超大计数（加 L）
float4约 ±3.4×10³⁸，6~7 位有效数字0.0f精度要求不高时（加 f）
double8约 ±1.8×10³⁰⁸，15~16 位有效数字0.0小数的默认选择
char20 ~ 65535（无符号）'\u0000'单个字符，本质是 Unicode 码值
boolean1true / falsefalse条件判断，不能用 0/1 代替

有两个地方容易反直觉。第一，char 是无符号的，范围从 0 开始，因为它表示的是字符编码而不是数量。第二，float 只有 4 字节，但范围比 8 字节的 long 还大——因为浮点数采用「符号位 + 指数位 + 尾数位」的表示法，牺牲精度换取了范围。所以 long 转 float 是允许的，但会丢精度。

另一个必须知道的现象是整数溢出：Integer.MAX_VALUE + 1 不会报错，而是直接变成最小值 -2147483648，因为最高位符号位被进位翻转了。这类错误静默发生，只能在设计时提前判断范围。

浮点数不能直接比较相等

0.1 + 0.2 == 0.3 的结果是 false。要比较两个 double 是否相等，应判断差值是否小于某个极小值，或直接改用 BigDecimal。金额、税率、利率这类场景尤其不能掉以轻心。

2.4引用类型：变量里装的其实是地址

基本类型存值，引用类型存「门牌号」。

除了八种基本类型，其余都是引用类型：String、数组、类、接口、枚举。声明 String name = "张三" 时，栈上的 name 只存一个地址，真正的字符串对象在堆里。这个区别在赋值时暴露得最彻底。

值与地址的区别java
int x = 10;
int y = x;          // 复制值
y = 20;             // x 不受影响，仍是 10

int[] a = {1, 2, 3};
int[] b = a;        // 复制地址，两个变量指向同一个数组
b[0] = 99;          // a[0] 也变成 99

这个行为常被误称为「引用传递」，其实 Java 只有值传递：方法接收到的是地址的副本。所以通过副本修改对象内容，原对象会变；让副本指向一个新对象，原引用不受影响。第 03 章讲方法参数时会再验证一次。

String 是个特例：它不可变，任何「修改」都会创建新对象，所以 s2 = s1; s2 += "x" 之后 s1 依然原样。这让 String 用起来像值类型，但也带来了拼接性能问题，第 06 章会专门讨论。

null 是什么

null 表示「这个引用没有指向任何对象」。它不等于空字符串 ""，也不等于 0。对 null 调用任何方法都会抛 NullPointerException，这是 Java 最常见的一类运行时异常。

2.5自动类型转换：小范围向大范围看齐

转换是安全的才自动，不安全的必须你亲自签字。

规则很朴素：小范围转大范围不会丢数据，所以编译器自动完成。链条是 byte → short → int → long → float → double，另外 char → int 也自动（得到 Unicode 码值）。反过来就必须强制转换。

真正需要留意的是表达式中的自动提升：任何小于 int 的整数类型（byte、short、char）参与二元运算时，会先统一提升为 int，所以 byte + byte 的结果是 int，直接赋回 byte 会编译报错。这是 Java 为了保证中间结果不溢出而做的保守设计。

自动转换java
int i = 100;
long l = i;          // 自动：int -> long
double d = l;        // 自动：long -> double

byte b1 = 10, b2 = 20;
// byte b3 = b1 + b2;      // 编译错误：结果是 int
int b3 = b1 + b2;          // 正确
byte b4 = (byte) (b1 + b2);// 需要时强转回去
自动转换也可能丢精度

long 转 float 是自动的，但 float 只有 6~7 位有效数字，超过部分会被舍入。一个 19 位的 long 转成 float 再转回来，数值已经变了。所以「自动」只代表不报错，不代表无损。

2.6强制类型转换：把风险摆到明面上

语法只是加一对括号，代价却可能是溢出。

格式是 目标类型 变量 = (目标类型) 值;。它的实现方式是直接截断二进制的高位，既不做四舍五入，也不做范围检查。所以 (int) 3.99 得到 3，(byte) 300 得到 44（300 减 256）。

强制转换的三种典型用途java
int a = (int) 3.99;                 // 3，截断小数
char c = (char) 66;                 // 'B'，码值转字符
int n = '7' - '0';                  // 7，字符数字转数字
byte b = (byte) 300;                // 44，溢出
long round = (long) (19.987 * 100 + 0.5) / 100;   // 四舍五入套路

实际开发中，强制转换主要出现在三个场景：取整（丢弃小数部分）、字符与码值互转、把运算结果收窄回原类型。理解它「按位截断」的本质，就不会对结果感到意外。

需要安全转换时，先用范围判断，或用会抛异常的 Math.toIntExact()——后者在溢出时抛 ArithmeticException，至少不会静默出错。工程上更推荐后者：让错误尽早暴露，而不是带着错误数据继续跑。

转换规则速记

同类型赋值 → 直接赋。小到大 → 自动。大到小 → 强转，可能溢出或丢精度。基本类型与字符串之间 → 不是强转，要用 Integer.parseInt() / String.valueOf() 这类转换方法。

小结这一章真正要记住的

Key takeaways

  1. 常量用 final，全大写命名，只赋值一次。 把「不该变的」固化下来，是降低维护成本最便宜的手段。
  2. 大括号决定作用域，作用域决定生命周期。 局部变量存栈、无默认值；成员变量存堆、有默认值。
  3. 八种基本类型的宽度是 1/2/4/8 字节，范围按 -2^(n-1) 推。 整数默认 int，小数默认 double，char 无符号。
  4. 引用类型变量存的是地址。 赋值复制地址，两个变量指向同一对象；Java 只有值传递。
  5. 自动转换只看范围是否变大，不看精度是否保留。 小于 int 的类型运算时会先提升为 int。
  6. 强制转换是截断高位，不做四舍五入、不报错。 需要安全时先判断范围，或用 toIntExact。

自测检查一下你真的懂了吗

为什么 byte b = 10; b = b + 1; 编译报错，而 b++ 可以？
b + 1 会提升为 int，赋回 byte 需要强转；b++ 是自增运算符，内部隐含了强制转换，等价于 b = (byte)(b + 1)。
(byte) 300 的结果是多少？为什么？
44。300 的二进制是 1 0010 1100，截取低 8 位得 0010 1100 = 44（即 300 - 256）。
基本类型和引用类型在赋值时有什么本质区别？
基本类型赋值传递值的副本，互不影响；引用类型赋值传递地址的副本，两个变量指向同一堆对象，通过任一变量修改都会反映到另一变量（String 因不可变而表现得像值类型）。
long 是 8 字节、float 是 4 字节，为什么 long 能自动转 float 却会丢精度？
float 用「1 位符号 + 8 位指数 + 23 位尾数」表示，范围大于 long，但有效数字只有 6~7 位十进制，尾数位不足导致低位被舍入。范围更大所以允许自动转换，精度不足所以会失真。
成员变量和局部变量在默认值上有什么区别？背后的原因是什么？
成员变量由 JVM 赋默认值（0、0.0、false、null），因为对象在堆上必须处于确定状态；局部变量无默认值，未赋值即使用会编译报错，借此彻底避免读取栈上的残留数据。
